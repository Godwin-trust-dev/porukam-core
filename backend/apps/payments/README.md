# apps.payments

Платёжный контур Э5, **волна 1** — прямой платёж с двусторонним подтверждением
(tech-spec.md §5.2.6, §6.3, §8.7; docs/plan.md «Этап 5»;
docs/adr/ADR-130-payments-direct-two-sided.md).

Платформа денег не держит и комиссию с платежа не берёт (финмодель v2, док 28;
ADR-055). Стороны платят как договорились — платформа фиксирует факт:
`Payment` выставляется по денежному ЛИСТУ дерева этапов, плательщик (заказчик)
и получатель (исполнитель) подтверждают его каждый со своей стороны, и только
двустороннее подтверждение закрывает `accepted -> paid`.

## Границы

**Работает сейчас:** способы `prepayment` (аванс как условие гейта §6.3 +
постоплата), `cash`, `external`.

**Отказывает честно:** `direct_platform`/`hold` — `409
payment_provider_not_configured`. Им нужен платёжный партнёр (Т-Банк, ЮKassa —
tech-spec.md §15.5), договора с которым нет. Эквайринг, СБП-сплит, холд/эскроу,
возвраты, `PayoutAccount`, `ProviderRoute`, раскладки «до подтверждения» —
следующая волна, вместе с партнёром. Комиссия за заключение (`apps.billing`)
отменена финмоделью v2 и здесь не появится.

**Отмена счёта** (`POST /payments/{id}/cancel`) — только постоплата из
`pending`. Аванс не отменяется: `409 payment_advance_not_cancellable`
(ADR-132) — он условие гейта §6.3, а `UNIQUE (milestone, kind)` не даёт
выставить его заново; ошибочный аванс лечится допником со сменой способа
расчёта.

## Направление зависимости — читать до правок

`apps.payments` импортирует `apps.milestones`/`apps.contracts`. **Обратного
импорта нет и быть не может:** `apps.contracts.services` статически достаёт до
`apps.milestones.services`, поэтому `apps.milestones -> apps.payments` сломал бы
контракт import-linter «contracts не импортирует payments» транзитивно.

Отсюда две вещи, которые выглядят необычно и сделаны нарочно:

1. Отметки `Milestone.*_confirmed_*_at` — денормализованное **зеркало** платежа
   с единственным писателем `services._mirror_into_milestone`. Оно даёт
   `apps.milestones` и `apps.dashboards` считать финансовое условие, не зная про
   это приложение.
2. Унаследованные `POST /v1/milestones/{id}/confirm-payment` и `/confirm-advance`
   живут в `api/urls.py` ЭТОГО приложения — URL, тело и ответ прежние, домен
   новый.
