# ADR-084. Google Drive BYO-бэкап доказательств: фиксация scope = drive.file

**Статус:** принято
**Дата:** 2026-08-13
**Контекст этапа:** ГВ.3 / после Э4 (`apps.evidence`, `docs/tasks/DEV-11`); companion-ADR к
`docs/tasks/Задача_feat_evidence-drive.md` (feat/evidence-drive)
**Тип:** упреждающее решение — фиксирует scope ДО написания реальной интеграции.

## Контекст

Модель хранения доказательств для GLOBAL уже спроектирована как «BYO-бэкап» (WhatsApp-модель):
платформа постоянно хранит только hash / миниатюру / метаданные, оригинал файла в GLOBAL не
оседает в S3 платформы — лежит временно в `transit_payload` до первой отдачи контрагенту, затем
обнуляется (`EvidenceOriginalUnavailableError`; `apps/evidence/services.py`,
`ADR_Log_p4_J_registries.md` п.8, `docs/tasks/global-wave.md` ГВ.3). Резервная копия оригинала —
в **личном Google Drive пользователя**.

Реальной интеграции с Google Drive API пока НЕТ: `apps/evidence/providers.py` содержит
`GoogleDriveBackupProvider` (Protocol) и единственную реализацию `FakeGoogleDriveBackupProvider`
(фейковые ссылки), эндпоинт `POST /evidence/{id}/backup` по умолчанию на фейке. В коде, `.env(.example)`
(backend и прод-конфиг) и зависимостях — **ни одной** scope-строки `.../auth/drive*`. Выбор scope
в `docs/tasks/DEV-11` вынесен как открытый вопрос («мок OAuth Drive scope, отдельно»; «Google Drive
OAuth (мок → GLOBAL-пакет после Э4)»), не как принятое решение.

Риск, который этот ADR закрывает: при реализации «на автомате» потянуться за широким scope
(`drive` / `drive.readonly`), потому что «так проще получить файл». Это переводит приложение в
разряд **restricted scope** → Google CASA security assessment (недели ожидания + ~$540/год),
что ставит под удар срок запуска. Узость хранения сама по себе scope не сужает — scope задаётся в
коде OAuth-клиента, а не архитектурой хранилища.

## Решение

- **Единственный Drive-scope продукта — `https://www.googleapis.com/auth/drive.file`.**
  Приложение создаёт и видит только свои файлы (файл бэкапа доказательства), доступа к остальному
  Drive пользователя не имеет. `drive.file` — **несенситивный** scope (Google рекомендует его именно
  для ухода от верификации): публикуется в Production без CASA и без недельного ревью.
- **Файл бэкапа виден пользователю в его Drive** — поэтому `drive.file`, а НЕ `drive.appdata`
  (скрытая папка приложения): по BYO-модели пользователь владеет своей копией и должен её видеть,
  как чат-бэкап в WhatsApp. `appdata` спрятал бы копию от владельца — противоречит смыслу «твой
  личный бэкап».
- **Запрет на restricted-scope в продукте зафиксирован явно:** `drive`, `drive.readonly`,
  `drive.metadata.readonly` и прочие широкие Drive-scope в проект НЕ добавляются. Если будущая фича
  реально потребует чтения чужих файлов пользователя — это отдельное решение с осознанным входом в
  CASA, а не побочный эффект реализации бэкапа.
- **Google Console:** при реализации включается Drive API и добавляется единственный scope
  `drive.file`; OAuth-клиент — тот же (`apps.accounts`, ADR-071), отдельный клиент не заводится.

## Альтернативы

- **`drive` / `drive.readonly` (широкий доступ).** Отклонено: restricted scope → CASA
  (время + деньги + ежегодный аудит), избыточен — для записи одного файла бэкапа чтение всего Drive
  не нужно.
- **`drive.appdata` (скрытая папка приложения).** Отклонено: прячет бэкап от самого пользователя,
  ломает BYO-смысл «это твоя копия, ты ей владеешь и видишь её».
- **Не фиксировать scope сейчас, решить при реализации.** Отклонено: именно момент реализации —
  когда легче всего случайно взять широкий scope ради скорости; дешевле зафиксировать узкий инвариант
  заранее (эта заметка), чем ловить restricted-scope на код-ревью или, хуже, после подачи на
  верификацию.

## Последствия

- Реализация Drive-бэкапа (после Э4) стартует с готовым, узким scope — путь к Production без
  верификации Google открыт по построению.
- Настройка Google Cloud для запуска (вход через Google) Drive не касается вообще: login-scope’ы
  (`openid/email/profile`) несенситивны, публикуются сразу; Drive API включается только когда
  реальная интеграция появится.
- Если продуктовое решение изменится и Drive-бэкап войдёт в октябрьский запуск — реализация +
  этот scope + включение Drive API становятся частью критического пути; но верификация всё равно не
  требуется, пока scope = `drive.file`.
