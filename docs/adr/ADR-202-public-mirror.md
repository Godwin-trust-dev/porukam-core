# ADR-202. Публичное зеркало porukam-core

**Статус:** принято (решение владельца 13.11.2026).
**Номер:** 202 — зарезервирован владельцем.

## Контекст

Нужны публичный код для портфолио и приём внешних контрибьюторов. Приватный репозиторий
содержит рабочие материалы (задачи, отчёты, финансовые модели, инфраструктуру прода и служебных
машин, персональные данные оператора в юридических текстах), история коммитов тоже. Скан истории
секретов не нашёл (отчёт аудита), но открывать историю целиком незачем.

## Решение

1. **Приватный репозиторий остаётся источником истины.** Разработка идёт в нём. Публичный
   репозиторий `Godwin-trust-dev/porukam-core` — производная копия.
2. **Сборка по белому списку путей.** `scripts/public-export/export.sh` берёт tracked-файлы
   ревизии по `allowlist.txt` (с исключениями), накладывает `overlay/` (README, LICENSE, NOTICE,
   CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, шаблоны GitHub, CI, англоязычные обзоры) и прогоняет
   сторожа: gitleaks, запрещённые строки (`patterns.txt`), публичные IPv4, запрещённые расширения,
   файлы больше 5 МБ, лексика красной линии в overlay. Провал сторожа означает отказ от коммита.
3. **Без старой истории.** Каждая публикация — один снапшот-коммит «Snapshot <дата> from
   <short-sha>» от noreply-адреса аккаунта GitHub. Скрипт ничего не пушит; публикует человек. Исключение из «одного коммита» — режим `--base`
   (см. «Обновление зеркала»): последующие снапшоты ложатся поверх истории porukam-core.
4. **Закрыто категориями:** юридические тексты оператора, рабочие задачи и отчёты, план, бэклог
   и финансовые модели, рабочий контекст и процедуры, аналитические снимки (открыты только
   SQL-запросы), маркетинг и скриншоты, конфигурации IDE, всё про прод и служебные машины
   (compose, nginx, скрипты, workflows), ADR про прод-инфраструктуру и коммерческую историю.
   Открыты код, тесты, технические доки, чек-листы каталога, публичные тексты магазина.
5. **Лицензия Apache-2.0**, правообладатель «Trust Dev»; сторонние компоненты — в NOTICE.
   **DCO** (`Signed-off-by`, `git commit -s`) вместо CLA. Товарные знаки «По рукам»/Porukam
   лицензией на код не передаются.
6. **Контрибьюторам нужны правила**: CONTRIBUTING.md повторяет слои, инварианты и терминологическую
   красную линию из внутренних правил проекта; линтер терминов остаётся в CI.
7. **Актуальность:** публикация снапшота — по решению владельца после слияния значимых изменений;
   принятые во внешних PR изменения переносятся в приватный репозиторий обратным патчем.

## Публичные патчи

`export.sh` применяет к выгрузке три правки (если шаблон не найден, экспорт падает); в приватном
репозитории файлы не меняются:

- `infra/docker/app/Dockerfile`: `ARG BASE_IMAGE=python:3.12-slim` вместо приватного зеркала в
  ghcr. Правило «FROM только из своего реестра» действует для CI и прода, где `BASE_IMAGE`
  передаётся явно.
- `web/index.html`: вырезается Cloudflare Web Analytics beacon (привязан к аккаунту владельца).
- `l10n/packs/*.json`: идентификация оператора в юридических текстах (ФИО оператора на латинице и
  кириллице) заменяется на `[OPERATOR NAME]`; затем в выгрузке пересчитывается
  `l10n/packs.lock.json` (`lock_packs.py`, затем `--check`). В приватном репозитории юр-тексты не
  меняются. Если шаблон не найден, экспорт падает. `merge_legal.py` в публичном дереве не
  применим (нет `docs/legal`).

## Уровни сторожа

`patterns.txt` задаёт уровень в первой колонке. ERROR проваливает экспорт: известные IP и
публичные IPv4, секреты, персональные данные и адреса оператора, локальные пути, служебная ВМ и
ключи, закрытые каталоги `infra/`, лексика терминологической красной линии. WARN попадает в отчёт:
ссылки на закрытые доки и ADR, имена workflows, имена провайдеров (в юридическом блоке
`l10n/packs/*.json` провайдеры названы намеренно, как обработчики персональных данных).

## Обновление зеркала

**Первый пуш** (porukam-core пуст): `export.sh` без `--base` делает корневой снапшот-коммит в
`--out`; владелец добавляет `origin` и пушит `main`. После этого на `main` включается ruleset
(без force-push, обязательный PR), поэтому история `main` дальше только растёт.

**Дальнейшие обновления** — без force-push, через PR:

1. Локальный клон porukam-core (чистое дерево, ветка `main`, свежий `git pull`) делает владелец;
   скрипт в сеть не ходит.
2. `export.sh --base <клон>`: выгрузка, патчи и сторож работают как обычно; затем в клоне
   удаляются все tracked-файлы, на их место копируется выгрузка, коммит «Snapshot <дата> from
   <sha>» создаётся на новой ветке `snapshot/<дата>-<sha>`. В `main` скрипт не коммитит. Если
   изменений нет, ветка не создаётся, код выхода 0.
3. Если в клоне есть файлы, которых нет в выгрузке (принятые внешние PR, не перенесённые в
   приватный репозиторий), скрипт печатает их список и отказывается продолжать без `--allow-delete`.
4. Владелец пушит ветку `snapshot/*` и открывает PR в `main` porukam-core.

**Перенос принятого внешнего PR в приватный porukam.** Иначе следующий снапшот его затрёт.
`git format-patch <старый main>..main` в клоне porukam-core, затем `git am` в ветку приватного
репозитория по правилам CLAUDE.md (feat/<приложение>, feat/web-*, chore/*; Conventional Commits).
Пути в публичной выгрузке совпадают с приватными, кроме файлов overlay и мест публичных патчей:
такие правки вносятся в `overlay/` или в патч `export.sh` вручную. После слияния в приватный
следующий снапшот уже содержит изменение.

## Политика GitHub Actions

Только GitHub-hosted раннеры (`ubuntu-latest`); триггеры `push` и `pull_request`, не
`pull_request_target`; `permissions: contents: read`; секретов в workflows нет. Self-hosted
раннер публичному репозиторию недоступен: форк-PR с чужим кодом не должен исполняться на наших машинах.
Приватные образы в реестре контрибьюторам недоступны, поэтому CI и локальная сборка не должны
зависеть от них (см. «Последствия»).

## Чек-лист настроек GitHub (для владельца)

- Secret scanning и push protection включены.
- Private vulnerability reporting включён.
- Dependabot alerts и security updates включены.
- CodeQL, default setup.
- Ruleset на `main`: без force-push и удаления, обязательный PR, обязательные проверки CI.
- Actions: approval для первых и внешних контрибьюторов; разрешения по умолчанию read-only;
  разрешённые actions ограничить.
- Группу self-hosted раннеров организации ограничить приватным репозиторием `porukam`.
- Пакеты контейнерного реестра оставить приватными, кроме решения о базовых образах.
- Включить Discussions по желанию; Issues с шаблонами из overlay.

## Последствия

- До первой публикации нужны правки в приватном репозитории: вычитка ADR и доков, замена
  контактных данных оператора в пакетах локализации и интерфейсе, чистка ссылок на закрытые
  материалы в комментариях, значения по умолчанию `fake` у провайдеров (запрет в production.py).
- Dockerfile ссылается на базовый образ из приватного реестра; в публичной выгрузке дефолт
  заменяется патчем на `python:3.12-slim` (см. «Публичные патчи»).
- Сторож (`checks.py`, `patterns.txt`) — часть процесса публикации; новые закрытые темы
  добавляются в `patterns.txt` и `allowlist.txt`.
