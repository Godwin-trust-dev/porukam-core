# ADR-187. Осмысленные пустые состояния каталога исполнителей на `/search` — фронт части 7

**Статус:** принято (план 11.09, часть 7 — «пустые состояния» поверх панели фильтров каталога,
ADR-185)
**Номер:** 187 — сверено по репозиторию и всем ворктри (`ls docs/adr ~/porukam-worktrees/*/docs/adr
| grep -o 'ADR-[0-9]*' | sort -u | tail`, максимум занятый на момент написания — 186, тот номер уже
использован соседним агентом).

## Контекст

ADR-185 оставила панель фильтров каталога (гео/сфера/опыт, `useCatalogSearch`) с ОДНИМ общим
пустым состоянием на любой промах: «Никого не нашлось» + кнопка «Сбросить фильтры» (раздел
«Известные пределы», прямая цитата — «нет отдельного разбора „фильтр сузил до нуля“ вовсе без
результатов от старта / разных типов пустоты»). Это неинформативно для человека: сброс ВСЕХ
фильтров теряет уже сделанный выбор (например, верно указанную сферу), когда на самом деле мешал
только один из них — обычно самый узкий.

## Решение

### Разбор на пять типов пустоты, а не один

`useCatalogEmptySuggestion` (`web/src/features/search/emptyState.ts`) вместо одного текста отдаёт
дискриминированное объединение `CatalogEmptySuggestion` — конкретный случай и связанное с ним
действие:

- **фильтров нет вовсе** (`no-data`) — каталог `catalog=1` без единого параметра сам по себе пуст:
  расширять нечего, действия нет вовсе («Пока никого нет», без кнопки);
- **сузили географию** (`widen-geo`) — на уровень ШИРЕ (город → регион → страна → мир, ровно
  ОДИН шаг) кто-то есть при тех же сфере/опыте: одна кнопка «Искать: {{название уровня шире}}»;
- **сузили сферой** (`remove-sphere` / `remove-geo` / `sphere-or-geo`) — по этой сфере в этом
  месте никого, но постановка задачи допускает три разных факта: помогает только убрать сферу
  (гео не виновато), помогает только убрать гео (сфера просто больше нигде так и не найдётся, дело
  не в месте), помогают оба по отдельности (сфера редкая, но не в этом месте ИЛИ не в размере
  фильтра гео) — предлагаем ИМЕННО те действия, которые проверкой подтвердились, не оба вслепую;
- **порог опыта отсекает всех** (`lower-experience`) — ближайший МЕНЬШИЙ пресет
  (`nearestLowerExperiencePreset`, `1/3/5/10` → на пресет ниже, `1` → «любой опыт») вместо «снять
  фильтр опыта» сразу — эффект тот же для человека («опыта поменьше»), но формулировка не
  предлагает первый же встречный порог, а конкретное следующее деление шкалы;
- **не помогло ничего из точечного** (`reset-all`) — прежнее поведение ADR-185 как последний
  рубеж: несколько фильтров одновременно отсекают всех так, что ни одно ослабление в отдельности
  не работает (например, сфера не существует НИГДЕ и порог опыта выше, чем у кого угодно) —
  честнее показать общий сброс, чем утверждать несуществующий частный совет.

### Приоритет — гео → сфера → опыт, самый узкий фильтр первым

Прямое указание владельца (план 11.09 §7, «несколько фильтров сразу — снимать по одному, самый
узкий первым»): гео обычно самый глубокий рычаг (три вложенных уровня против одного плоского
списка сфер и одной шкалы опыта), поэтому его пробуют ослабить первым, и только если это НЕ
помогает — переходят к сфере, и только если не помогло НИЧЕГО из гео и сферы — к порогу опыта.
Гео проверяется в один-единственный шаг «на уровень шире», а не полным перебором до мира: цель —
конкретный совет («ещё один клик»), а не «попробуйте всё сразу».

### «А есть ли кто-то шире?» — дополнительный запрос, но не лишняя нагрузка

Бэк каталога (ADR-184) не отдаёт фасетов/счётчиков — узнать, помогло бы ослабление, можно только
реальным запросом с ослабленным фильтром. `probeCatalogNonEmpty` (`features/search/api.ts`) —
тот же эндпоинт `GET /dashboard/search`, что и основная выдача, но `limit: 1` (нужен только факт
непустоты, не строки) и без пагинации. Почему это не лишняя нагрузка:

- запрос уходит СТРОГО когда основная выдача уже пуста (`enabled: isEmpty` в
  `useCatalogEmptySuggestion`) — не на каждое открытие страницы и не на каждое изменение панели,
  которое и так уже само по себе запрос;
- пробы для разных осей (гео/сфера/эффект удаления гео при активной сфере/опыт) летят
  ПАРАЛЛЕЛЬНО (`useQueries`), а не водопадом — общее время ожидания ограничено самым медленным
  ОДНИМ запросом, а не суммой;
- активны только пробы для факторов, которые действительно СУЖИВАЮТ (гео-проба — только если
  гео-фильтр стоит, сфера-пробы — только если выбрана сфера, и т.д.) — на пустом фильтре или
  единственном активном факторе лишних проб нет вовсе;
- пока пробы не отработали, экран показывает нейтральный скелетон (`checking`), а не мигает
  неверным советом, который тут же сменился бы правильным.

Верхняя граница — 4 параллельных пробных запроса (гео-расширение, снятие сферы, снятие гео при
активной сфере, понижение порога опыта) на одну пустую выдачу, и то только когда ВСЕ соответствующие
фильтры активны одновременно.

### Гео проверяется на ОДИН уровень шире, а не до конца

`widenGeoFilter` (`features/search/geoFilter.ts`) снимает самое глубокое непустое поле фильтра
(город → регион, регион → страна, страна → мир) — симметрично тому, что уже показывает
`GeoFilterSheet` строками «Вся страна: …» / «Только регион, без города» (ADR-185). Если ослабление
на один уровень не помогает, `useCatalogEmptySuggestion` НЕ пробует уровень ещё шире отдельным
запросом — переходит к проверке сферы/опыта (приоритет по разделу выше), а не эксплуатирует гео
до предела. Если в итоге ничего не помогло — общий сброс (`reset-all`) всё равно снимет гео
целиком, так что человек не застревает: разница только в формулировке промежуточного совета, не
в достижимости результата.

### Убрать СФЕРУ или убрать ГЕО — оба варианта, только когда оба подтверждены

`sphere-or-geo` — не эвристика «раз оба фильтра активны, предложим оба» (это было бы вслепую):
`remove-sphere`/`remove-geo` пробуются НЕЗАВИСИМЫМИ запросами (снятие сферы при том же гео / снятие
гео при той же сфере), и оба действия показываются, только если ОБА запроса подтвердили результат.
Если сработало только одно — показывается только оно, второе не предлагается ложно.

## Тексты — тон продукта

Заголовок описывает СИТУАЦИЮ («Здесь никого не нашлось», «По этой сфере здесь никого нет»),
кнопка — САМО действие с его результатом, а не команду в пустоту («Искать: Ленинградская область,
Россия», «Снизить порог: 3+ завершённых сделок») — тот же приём, что уже применён в
`GeoFilterSheet` (`searchGeoWholeCountry`/`searchGeoWholeRegion`, ADR-185): кнопка ПОКАЗЫВАЕТ, что
получится, а не просит поверить на слово. `searchExperienceMinOption`/`searchExperienceAny`
переиспользованы буквально (та же подпись, что в самом `SelectField` порога) — новое значение
после клика выглядит ТЕМ ЖЕ текстом, что человек уже видел в списке пресетов.

## Пределы (сознательно не в этой ветке)

- **Гео проверяется на один уровень, не «до победного» перебором всех уровней сразу.** Если
  ослабление на один уровень не помогает, а помогло бы более широкое (например, соседняя область
  того же региона, до которой ADR-187 не долистывает), человек увидит совет по сфере/опыту или
  общий сброс раньше, чем второй гео-шаг. Обоснование — в разделе выше; расширение до полного
  перебора уровней гео, если понадобится, — отдельная последующая правка, не архитектурное
  решение.
- **Счётчика «поисков с фильтром» здесь нет** — аналитика (план 11.09 §7, вторая половина) ведётся
  отдельным агентом в `apps.analytics`, backend этой веткой не тронут.
- **Проверка «шире» не различает вложенность самой сферы или таксономию** — только гео/сфера/опыт
  по отдельности, ровно те три оси, что есть у панели фильтров (ADR-185). Комбинированных
  предложений вида «снять И сферу, И понизить опыт одновременно» нет: `reset-all` — единственный
  вариант, когда ни одна ось по отдельности не работает (см. «Приоритет» выше).
- **Пробные запросы не кешируются между открытиями страницы дольше `staleTime` (10 с)** — то же
  окно, что у обычной выдачи каталога; отдельного долгоживущего кеша под пробы не заводили.

## Тесты

`web/tests/SearchCatalogEmptyStates.test.tsx` — каждая ветка `useCatalogEmptySuggestion` на
детерминированных ответах `/dashboard/search` (реальный мок-датасет каталога подобрать под ТОЧНО
одну ветку за раз сложнее, чем нужно для модульной проверки): фильтров нет вовсе, гео сузило (клик
по кнопке действительно меняет URL и фильтр, а не просто текст), сфера сузила тремя разными
исходами (только «убрать сферу», только «убрать гео», оба сразу), порог опыта (снижение до
ближайшего пресета и до «любой опыт», когда пресет уже минимальный), комбинация фильтров, которую
точечно не починить — общий сброс. `web/tests/searchEmptyStateHelpers.test.ts` — чистые функции
`widenGeoFilter` (город/регион/страна/мир, включая гео-фильтр без сохранённого региона) и
`nearestLowerExperiencePreset` (стандартные пресеты и нестандартное значение из ручной правки URL).
`web/tests/SearchCatalogFilters.test.tsx` — старый тест общего пустого состояния (ADR-185) заменён
на комбинацию, которая при новом разборе ДЕЙСТВИТЕЛЬНО остаётся общим сбросом (несуществующая сфера
+ порог опыта выше, чем у любого профиля выбранной страны), — предыдущая комбинация с приходом
ADR-187 стала попадать в конкретную ветку («убрать сферу»), что и является целью этой ветки.
