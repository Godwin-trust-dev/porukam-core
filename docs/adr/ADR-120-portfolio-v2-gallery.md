# ADR-120: Портфолио v2 — галерея до 5 фото, обязательная дата завершения, редактирование

Дата: 2026-08-24. Статус: принят. Расширение ADR-115.

## Контекст

Отсмотр 2026-08-24 (docs/backlog.md «Портфолио v2»): «поле работы не кликабельное, не получается
провалиться и посмотреть описание; давай проекты можно редактировать; при создании обязательно
указывать даты выполнения, город — опционально; описание просторное; 5 фото на проект, первая —
основная». ADR-115 дал одну фото-обложку (`PortfolioProject.photo_key`) и создание без дат;
`PATCH` умел только title/description/location/media/order.

## Решения

### 1. `PortfolioPhoto` — галерея, `photo_key` проекта остаётся зеркалом основного фото

Новая модель `PortfolioPhoto(project, photo_key, order, created_at)`, до `PORTFOLIO_MAX_PHOTOS = 5`
на проект, основное — `order == 0`. Тот же байтовый пайплайн, что обложка (WebP 1280/320, ключ
`portfolio/<profile_id>/<uuid7>`, S3/fake). Миграция 0007 переносит существующую обложку в первое
фото. `PortfolioProject.photo_key` НЕ удаляется: сервис держит его равным ключу `photos[0]`
(`_sync_cover`), поэтому `photo_url`, `GET /portfolio/projects/{id}/photo` и старые бандлы
работают без изменений — деплой бэка не зависит от фронта. Порядок пересчитывается без дыр после
удаления/смены основного.

### 2. API

- `POST /portfolio/projects/{id}/photos` (multipart `file`) — добавить в конец; 409
  `portfolio_photos_limit` на шестое; 413/422 — как у обложки.
- `GET /portfolio/projects/{id}/photos/{photo_id}?size=1280|320` — AllowAny (витрина), фото
  строго внутри проекта из URL (чужой id → 404).
- `DELETE .../photos/{photo_id}` — следующее становится основным.
- `POST .../photos/{photo_id}/primary` — сделать основным.
- `POST/DELETE .../photo` (ADR-115) остаются как «заменить/убрать основное фото».
- `PortfolioProjectSerializer` +: `photos: [{id, url, order, is_primary}]`, `started_at`.

### 3. Даты и редактирование

`completed_at` обязательна при создании ручного проекта (сериализатор `required`, сервис — 422
`portfolio_dates_invalid`, в т.ч. `started_at > completed_at`); `started_at` и `location_label`
(город) — опциональны. `PATCH` принимает также `sphere`, `started_at` (`null` снимает), `completed_at`
(снять нельзя). `FROM_CONTRACT`-проекты не трогаются: дата может быть неизвестна системе.
Описание — `TextField` без лимита; лимит не вводится и на фронте.

### 4. Фронт (парный PR `feat/web-portfolio-v2`)

Карточка проекта: галерея миниатюр, добавление до 5, удаление, «сделать основным»; форма
создания/редактирования: даты (завершение обязательно), город, просторное описание; на карточке
репутации работы кликабельны → просмотр проекта (галерея + описание + даты + город).

## Последствия

- Мобильные/старые клиенты, шлющие `POST /projects` без `completed_at`, получат 400 — фронт v1
  этого поля не слал, поэтому парный веб-PR обязателен до деплоя обоих.
- Объекты удалённых фото удаляются физически (как аватары); восстановления нет.
