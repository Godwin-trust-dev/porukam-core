# ADR-104. `DELETE /contracts/{id}` — удаление черновика договора

Дата: 2026-08-21. Статус: принято.
Ветки: `feat/contracts-draft-delete` (бэкенд, этот ADR), `feat/web-draft-edit-delete` (UI).

## Контекст

tech-spec.md §8.4 даёт черновику `POST /contracts`, `PATCH /contracts/{id}`
и `POST …/send`; удаления нет. В проде у пользователя накопились черновики,
которые нельзя убрать из списка «Сделки» (отсмотр 2026-08-21: «черновики —
надо дать возможность удалять, чтобы не висели»). Отдельно: мастер после
создания черновика блокировал шаг «Тип» («создайте новый договор»), хотя
`patch_draft` смену типа/сторон умеет — тупик плодил новые черновики вместо
правки старого.

## Решение

`DELETE /contracts/{id}` → `204`, сервис `apps.contracts.services.delete_draft`:

- только `negotiation_status = draft`, иначе `409 draft_not_editable` —
  после отправки договор виден контрагенту, дальше только отзыв/отклонение
  по FSM согласования (Э4.2);
- любая из сторон (как у PATCH), чужой — `403`;
- жёсткое удаление: до заморозки договор не юрзначим — ни `ContractVersion`
  (FK `PROTECT` — дополнительная страховка от удаления не-черновика), ни
  подписей, ни платежей. Стороны, этапы, документы, доказательства —
  каскадом по FK. Мягкого удаления не заводим (CLAUDE.md);
- событие `contract.draft_deleted` в outbox (симметрично `drafted` /
  `draft_patched`). Лента уведомлений (ADR-102) резолвит мету при чтении и
  на отсутствующем договоре отдаёт пункт без контекста, не 404.

UI: черновик получает «Редактировать» (мастер на шаге с подстановкой
`draftId`/типа/сферы из договора) и «Удалить» с подтверждением — в списке
сделок, в панели и в карточке. Шаг «Тип» больше не блокируется: смена типа
идёт через существующий `PATCH` (`client_option`/`contract_type_code`),
бэк пересчитывает `segment`.

## Последствия

- В `docs/tech-spec.md` §8.4 добавить строку `DELETE /contracts/{id}` при
  следующей ревизии спеки.
- Поисковые/кэш-проекции, если появятся, подписываются на
  `contract.draft_deleted`.
