# ADR-097. Нечёткий поиск сфер и локализация категорий каталога

Дата: 2026-08-19. Статус: принято.
Ветки: `feat/catalog-sphere-search` (бэкенд, этот ADR), `feat/web-sphere-search` (UI).

## Контекст

Отсмотр мастера создания договора (шаг «Сфера») дал три замечания:

1. Поиск «вообще не работает»: `GET /spheres?q=` матчил запрос как
   **префикс** локализованного имени сферы (ADR-091 §4). Запрос из
   собственного плейсхолдера UI («ремонт кухни») не находил ничего;
   опечатка («римонт») — тоже ничего.
2. Выбранная сфера и строка поиска на фронте никак не связаны
   (разобрано в ветке UI).
3. Под-сферы (виды работ) не локализованы: `GET /work-types` отдаёт
   `name == code` (сырые слаги `turnkey`, `climate`, …) — у категории
   чек-листа нет человекочитаемого имени НИГДЕ в данных, ни на одном
   языке. Плюс ~10 из 17 сфер посеяны импортёром чек-листов только с
   `{"ru": …}` в `name_i18n` — в любой не-ru локали они падали в русский,
   хотя в языковых пакетах (`l10n/packs/*.json`, `catalog.spheres.*`)
   переводы всех 18 сфер на 29 языков давно есть и не использовались.

## Решение

### 1. Поиск — `apps.catalog.search` (чистый модуль, без ORM)

По практике каталожных поисков (Baymard/Algolia/Meilisearch):

- нормализация (нижний регистр, ё→е, пунктуация → пробел), по-токенное
  сравнение: точное слово > префикс > подстрока > опечатка
  (Дамерау-Левенштейн; допуск от длины токена: ≤3 — 0, 4–7 — 1, ≥8 — 2);
- достаточно совпадения одного токена запроса (больше совпало — выше),
  фразовый бонус за вхождение запроса в имя целиком;
- кандидаты сферы — её имена (все значения `name_i18n` + имя из пакета
  запрошенной локали) **и имена её категорий** («сантехника» находит
  «Ремонт и строительство»); совпадение по категории весит 0.8 имени.

Каталог — 18 сфер, всё считается в памяти на запрос; никакого
`pg_trgm`/полнотекста не заводим (не тот масштаб). Подсказки в UI — это
и есть ранжированный `results` (отдельного suggest-эндпоинта нет).

### 2. Имена категорий — новый namespace `catalog.categories` в пакетах

Ключ — `<sphere_code>.<category_code>` (категории глобально не уникальны:
`other` почти в каждой сфере), 105 ключей на язык, во всех 29 пакетах.
RU-имена извлечены из заголовков исходных CL-файлов
(`### N.N. \`сфера.категория\` — Имя`), которые парсер ADR-081 сознательно
не сохранял; для `sales.*`/`other.other` (в файлах только слаги) имена
даны заново. Остальные языки переведены конвейером контент-пакетов
(как и прочий каталожный контент, quality=machine).

`GET /work-types` резолвит `name` через новый bulk-селектор
`apps.l10n.selectors.get_catalog_map("categories", locale=…)` (фолбэк
locale → en на уровне ключа, не больше двух чтений `LocalePack` на
запрос — `get_catalog_text` в цикле делал бы по два на код). Фолбэк без
импортированных пакетов — прежний `name == code`. Для ru имя тоже из
пакета: у категории нет `name_i18n`, «RU-контур отдельно» здесь
неприменим — другого источника не существует.

### 3. Имена сфер для не-ru локалей — из пакетов

`GET /spheres` для локали ≠ ru берёт имя из `catalog.spheres.*` пакета
(фолбэк — прежний `name_i18n`); для ru — по-прежнему `name_i18n`
(RU-контур на своём механизме, докстринг `apps.l10n.selectors`
не нарушаем). Это законный импорт: `apps.catalog` и `apps.l10n` — один
нижний слой, контракт import-linter не запрещает catalog → l10n
(и обратного импорта у l10n нет — цикла не возникает).

## Отвергнутые варианты

- **Модель `WorkCategory` в catalog** (name_i18n, миграция, расширение
  парсера ADR-081): второй источник правды рядом с пакетами, где уже
  живёт весь переводимый каталожный контент; миграция и версионирование
  ради данных, которые по своей природе — контент, не схема.
- **pg_trgm / полнотекст**: 18 строк-кандидатов, in-memory Python
  быстрее и тестируется без живой БД.
- **Отдельный suggest-эндпоинт**: дублировал бы `GET /spheres?q=` —
  ранжированный список и есть подсказки.

## Последствия

- `pack_version` всех 29 пакетов поднят (checksum меняется).
- Тест ADR-091 «name == code» переориентирован: это теперь фолбэк-режим
  (БД без пакетов), локализованные имена закреплены отдельными тестами
  на реальных ru/en-пакетах репозитория.
- Фронт обязан слать в `GET /checklist-recommendations?workType=` КОД
  категории, не отображаемое имя (раньше они совпадали) — правка в
  ветке UI.
