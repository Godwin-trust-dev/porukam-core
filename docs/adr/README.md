# ADR-журнал репозитория — индекс

Новые архитектурные решения — отдельными файлами `ADR-NNN-*.md`, в том же PR, что и код,
который они описывают.

## Два независимых ADR-журнала — не путать номера

В проекте существуют **два независимых журнала ADR**, у каждого своя нумерация:

- **Внешний журнал** («Trust Economy», реестры A–J) — продуктовые/архитектурные
  решения, принятые ДО кода, вне этого репозитория. На момент старта репозитория доходил
  примерно до ADR-056, поэтому репо-журнал начал нумерацию с 057. Внешний журнал продолжает
  жить и расти независимо (в нём есть, например, свои ADR-057…060+, в т.ч. отдельные
  ADR-059 «приватность/находимость» и ADR-060 «GLOBAL»). Копия журнала лежит в этом же
  каталоге: [`ADR_Log_p1_A-D.md`](ADR_Log_p1_A-D.md) (разделы A–D, ADR-001–020),
  [`ADR_Log_p2_E-G.md`](ADR_Log_p2_E-G.md) (E–G, ADR-021–039),
  `ADR_Log_p3_H-I.md` (H–I, ADR-040–058; внутренний, не публикуется),
  `ADR_Log_p4_J_registries.md` (J, ADR-059–060 + реестры
  отложенных решений). Сверяться с ними до того, как счесть совпадение номеров случайным.
  Черновики/финал самого внешнего ADR-059 — отдельно:
  [`ADR-059_finalization_prep.md`](ADR-059_finalization_prep.md),
  [`ADR-059_privacy_findability_visibility.md`](ADR-059_privacy_findability_visibility.md).
- **Журнал этого репозитория** (`docs/adr/`) — решения, принятые в ходе разработки, начиная
  с ADR-057.

Диапазоны **пересекаются** и это нормально — тождество номеров между двумя журналами
**не предполагать**. При ссылке на решение всегда указывать, какой журнал имеется в виду:
писать **«репо-ADR-NNN»** и **«внешний ADR-NNN»**, а не просто «ADR-NNN», если контекст не
исключает двусмысленность. Пример разночтения зафиксирован в самом журнале: заголовок
`ADR-059-envelope-encryption-common.md` (репо, этап 3.1, шифрование ПД) и «ADR-059» из
дельты этапа 3.3 (внешний журнал, «финал приватности/находимости», см.
`ADR-067-social-consent-profile-visibility.md`) — это два разных документа, числа совпали
случайно.

### Правило для новых ADR

Перед созданием нового ADR: свериться с таблицей ниже, номер = (последний номер в таблице) + 1.
Не переиспользовать пропущенные номера (см. раздел «Пропущенные номера») и не опираться на
нумерацию внешнего журнала.

**Почему это правило нарушалось дважды** (см. «Исторический контекст» ниже): несколько веток
одновременно брали «следующий свободный номер» из своего локального состояния `docs/adr/`,
не дожидаясь мёржа друг друга — коллизия обнаруживается только постфактум, когда обе ветки
уже в `main`. Единственная надёжная защита — сверяться с этим файлом **на актуальном `main`**
непосредственно перед мёржем PR, а не только в момент создания ветки.

## Исторический контекст

Исходный журнал ADR-001…058 — во внешнем журнале проекта Trust Economy, не
воспроизведён в этом репозитории.

До 2026-08-05 в репо-журнале существовал дубль номера: два файла `ADR-065-*.md` — «Audit
Vault» (ЭФ.3) и «Реестр доменных дедлайнов» (ЭФ.2), оба датированы 2026-07-31. Первая попытка
устранить дубль (переносом второго решения на номер 069) готовилась в отдельной ветке
параллельно с `chore/prod-infra`, которая тем временем сама заняла 069 под другое решение —
к моменту повторной попытки 069 был уже занят, и «свободный номер» пришлось пересчитывать
заново. Итоговый перенос — на 072; Audit Vault остался под номером 065.

Второй, отдельный дубль возник тем же путём 2026-08-06: `feat/jurisdictions-global` (ГВ.1) и
`feat/contracts-signing` (Э4.4) независимо взяли номер 070 для своих ADR, не дожидаясь мёржа
друг друга. По хронологии мёржа в `main` (`feat/jurisdictions-global` — PR #34, раньше)
номер 070 остался за ГВ.1; Э4.4 перенесён на 073 (первый свободный номер на момент
устранения ОБОИХ дублей одним PR).

Третий, тоже независимый дубль возник в тот же день ещё раз, уже во время устранения первых
двух: `chore/adr-journal` (эта работа, номер 072 для перенесённого «Реестра доменных
дедлайнов») и `feat/authority-profiles` (этап 3.5, отдельно взявшая 072 для своего решения)
были смёржены в `main` почти подряд — `chore/adr-journal` первой (PR #39), `feat/
authority-profiles` следом (PR #38 по номеру PR, но фактически позже по времени мёржа).
Номер 072 остался за «Реестром доменных дедлайнов» (смёржен первым); authority-profiles
перенесена на 074 — первый свободный на момент этого исправления.

Итог: три расхождения подряд за один день — не совпадение, а системный эффект нескольких
одновременно открытых веток, ни одна из которых не видела чужих ADR-файлов до мёржа. Пока
такого не появится автоматическая проверка в CI (см. блок «Правило для новых ADR» выше),
единственная защита — ручная сверка с этим файлом непосредственно перед мёржем, а не при
создании ветки.

Содержание всех переносимых решений не менялось — правки только номеров, имён файлов и
ссылок на них по репозиторию (`docs/tasks/chore-adr-journal.md` фиксирует историю
обнаружения и исправления; этот README — актуальное состояние после трёх расхождений).
