# ADR-135: Служба доверенных меток времени для суточного чекпойнта

**Статус:** Accepted
**Дата:** 2026-08-26
**Решение принято:** владелец продукта
**Область:** доказательная архивация, слой меток времени

---

## Контекст

Система ведёт доказательный архив: раз в сутки формируется чекпойнт, и на его корень
ставится доверенная метка времени (RFC 3161), подтверждающая, что данные существовали
не позже указанного момента и не менялись задним числом.

Метка ставится **на корень суточного чекпойнта, а не на каждый файл** — это
принципиальное решение, снижающее объём обращений к TSA с тысяч в сутки до единиц.

Силы, действующие на решение:

- **Продукт ориентирован на глобальный рынок.** Российская версия с ГОСТ-криптографией —
  отдельный платный скоуп по запросу, в основной продукт не входит.
- **Метку нельзя поставить задним числом.** Метка доказывает «существовало не позже T»,
  где T — момент штампования. Каждый день без TSA — безвозвратно потерянный день
  доказательной базы. Это делает задержку внедрения дороже, чем сама услуга.
- **Исходящий трафик боевого хоста** — VPS у Hoster.KZ (AS200532, Казахстан),
  не Yandex Cloud. Казахстанский egress не попадает под санкционные фильтры,
  которых мы опасались для российского IP.
- **Бюджет на старте — ноль.** Платные варианты рассматриваются как следующий шаг.

### Что было измерено

Проба RFC 3161 (`openssl ts -query` + POST) с боевого хоста, 2026-08-26:

| TSA | HTTP | Время | Статус |
|---|---|---|---|
| `tsa.swisssign.net` | 200 | 0.25 c | Granted |
| `timestamp.sectigo.com/qualified` | 200 | 3.36 c | Granted |
| `timestamp.entrust.net` | 200 | 0.50 c | Granted |
| `time.certum.pl` | 200 | 0.62 c | Granted |
| `ts.ssl.com` | 200 | 0.60 c | Granted |
| `timestamp.digicert.com` | 200 | 0.58 c | Granted |
| `timestamp.globalsign.com/advanced` | 200 | 0.53 c | Granted |
| `timestamp.apple.com/ts01` | 200 | 0.57 c | Granted |
| `freetsa.org/tsr` | 200 | 0.82 c | Granted |
| `rfc3161.ai.moda` | 200 | 0.48 c | Granted |
| `timestamp.sectigo.com` | 200 | 0.48 c | Granted |
| `tsa.baltstamp.lt` | — | 30 c | **timeout** |

Гео-блокировок не обнаружено. Регистрация ни у одного из бесплатных TSA не требуется:
RFC 3161 — stateless HTTP POST без аккаунтов и ключей.

**Важно о методике:** первые два прогона были невалидны — первый уходил через VPN
с американской локацией, второй считался запущенным на ВМ Yandex Cloud, которой на
деле не оказалось. Валиден только третий, выполненный на реальном боевом хосте.
Любую будущую проверку доступности проводить **на том хосте, где выполняется cron**,
и фиксировать `curl -s https://ifconfig.co/json` в том же логе.

## Решение

Ставим метку на корень суточного чекпойнта **параллельно у четырёх независимых TSA**.
Чекпойнт считается заверенным при кворуме 2 из 4.

```
TSA_ENDPOINTS = [
  "http://tsa.swisssign.net",                 # CH — вне ЕС и США
  "http://time.certum.pl",                    # PL — ЕС, Asseco
  "http://timestamp.sectigo.com/qualified",   # EU Trust List, qualified
  "https://freetsa.org/tsr",                  # DE — запасной
]
TSA_QUORUM  = 2      # меньше — чекпойнт помечается как незаверенный
TSA_TIMEOUT = 10s    # sectigo-qualified измерен на 3.4 c
TSA_NONCE   = true   # обязательно: без nonce не отличить свежий ответ от кеша
```

Отбор — по декорреляции отказов, а не по количеству. Юрисдикция и оператор у всех
четырёх разные, поэтому одно санкционное или коммерческое решение не выключает больше
одного узла.

**Исключены сознательно:**

- `rfc3161.ai.moda` — балансировщик поверх чужих TSA. Отдаёт метку того, к кому
  переадресовал, независимым свидетелем не является и коррелирует с уже включёнными.
- `timestamp.apple.com/ts01` — привязан к code signing Apple, в правовой записи неуместен.
- `tsa.baltstamp.lt` — не отвечает.
- `digicert`, `ssl.com`, `entrust` — работоспособны, но все три из США. Добавление
  второго и третьего американского TSA не увеличивает независимость: политика у них
  меняется синхронно.

## Рассмотренные варианты

### Вариант A: ГОСТ-штамп аккредитованного российского УЦ

| Измерение | Оценка |
|---|---|
| Сложность | Высокая — КЭП организации, КриптоПро CSP, сертифицированная сборка |
| Стоимость | Сигнал-КОМ от 20 000 ₽/квартал (≈80 000 ₽/год); КриптоПро TSP Server 210 000 ₽ |
| Юридический вес | Максимальный в РФ-суде, около нулевой за её пределами |
| Соответствие скоупу | Не соответствует: продукт глобальный |

**За:** единственный вариант, который российский суд примет без объяснений.
**Против:** ×2000 к стоимости бесплатного варианта; тянет в стек российскую
криптографию с лицензиями; не нужен глобальному продукту.

### Вариант B: платный eIDAS-qualified TSA (Disig и аналоги)

| Измерение | Оценка |
|---|---|
| Сложность | Низкая — тот же RFC 3161, плюс учётная запись |
| Стоимость | Disig: пакет 500 шт — €39,17 без НДС (€0,078/шт) ≈ €29–40/год при 365 метках |
| Юридический вес | Презумпция точности даты/времени, ст. 41 Регламента (ЕС) 910/2014 |
| Блокер | Оплата из РФ в ЕС — нужен не-российский платёжный контур |

**За:** самая дешёвая юридическая функция в системе; SLA и договор, в отличие от бесплатных.
**Против:** упирается не в цену, а в платёжное юрлицо.

### Вариант C: бесплатные публичные TSA, несколько параллельно ← **выбран**

| Измерение | Оценка |
|---|---|
| Сложность | Низкая — четыре HTTP-запроса в сутки |
| Стоимость | 0 |
| Юридический вес | Техническое доказательство; презумпции ст. 41 нет (кроме qualified-эндпоинта) |
| Риск | CPS без гарантий; часть провайдеров формально ограничивает использование code signing |

**За:** внедряется сегодня, а каждый день отсрочки — потерянный день доказательств.
**Против:** нет договора, нет SLA, юридически слабее квалифицированной метки.

## Анализ компромиссов

Ключевой компромисс — **скорость внедрения против юридического веса**, и он разрешается
в пользу скорости из-за необратимости. Слабую метку можно позже усилить, поставив рядом
квалифицированную; отсутствующую метку восстановить нельзя вообще. Поэтому бесплатный
вариант выбран не как экономия, а как способ не терять доказательства, пока решается
вопрос с платным.

Второй компромисс — **количество TSA против сложности**. При одном запросе в сутки
предельная стоимость четвёртого провайдера практически нулевая (один HTTP-запрос,
несколько килобайт), поэтому экономить на количестве смысла нет. Ограничитель —
не ресурсы, а внятная семантика отказа, которую и задаёт кворум.

Третий — **глобальный продукт против российского рынка**. Решение выводит ГОСТ из
скоупа, но обязано оставить дверь открытой дёшево (см. «Последствия»).

## Последствия

**Становится проще:**

- Стек без российской криптографии: ни КриптоПро CSP, ни КЭП, ни сертифицированных сборок.
- Затраты на метки — ноль, вопрос бюджета снят со старта.
- Отказ одного провайдера не роняет чекпойнт.

**Становится сложнее:**

- Метки юридически слабее квалифицированных: в споре их придётся объяснять суду,
  а не предъявлять.
- Зависимость от бесплатных сервисов без договора и SLA — условия могут измениться
  без уведомления.
- Появляется требование архивировать цепочки сертификатов, которого при одном
  провайдере было бы меньше.

**Придётся пересмотреть:**

- Когда появится не-российское платёжное юрлицо — добавить платный QTSP (Вариант B).
- Если возникнет реальный российский судебный сценарий — вернуться к Варианту A,
  что возможно только при выполнении пунктов 5–6 ниже.
- Метки стареют вместе с криптографией: через несколько лет потребуется rollover —
  перештамповка новых меток поверх старых. Закладывать сейчас не нужно, но формат
  хранения должен допускать несколько слоёв меток на один чекпойнт.

## Требования к реализации

Пункты 5 и 6 — единственное, что сохраняет возможность российской версии.
Без них ГОСТ-вариант задним числом не собирается ни за какие деньги.

1. **Nonce в каждом запросе.** Без него нельзя отличить свежий ответ TSA
   от закешированного или подменённого.

2. **Кворум как явная семантика.** Меньше `TSA_QUORUM` успешных ответов — чекпойнт
   помечается как незаверенный. Без этого отказ провайдера либо роняет всё,
   либо не замечается — оба поведения неверны.

3. **Архивировать цепочку сертификатов на момент штампования** — вместе с `.tsr`,
   включая CRL/OCSP-ответ того момента. Сертификат TSA живёт 3–10 лет; при проверке
   метки через пять лет он истечёт, и без архивной копии цепочки проверка не сойдётся.
   Метка останется настоящей, а доказать это будет нечем. Самая частая ошибка
   в подобных схемах.

4. **Алерт на недобор кворума.** Не поставившаяся метка выглядит как отсутствие
   данных, а не как ошибка, и обнаруживается через полгода — когда она понадобилась.

5. **Алгоритм хеша — поле записи, а не константа:** `{"alg": "sha256", "root": "..."}`.
   ГОСТ-TSA требует, чтобы message imprint был хешем Стрибог (ГОСТ Р 34.11-2012).
   При зашитом SHA-256 добавление ГОСТ превращается в миграцию формата.

6. **Хранить содержимое чекпойнта, а не только корень.** Пересчитать корень Стрибогом
   можно лишь имея листья.

7. **Идентификатор хоста в записи чекпойнта.** Текущий `hostname` — `server`,
   что через пять лет не идентифицирует ничего. Для доказательного архива
   «какая машина это выпустила» — часть доказательства.
