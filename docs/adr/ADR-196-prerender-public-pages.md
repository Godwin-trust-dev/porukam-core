# ADR-196. Пререндер публичных страниц: статический HTML на 29 языках рядом с оболочкой SPA

**Статус:** принято (решение владельца 29.10.2026 — «сразу с prerender»).
**Номер:** 196 — сверено по репозиторию и всем ворктри, максимум занятый на момент
написания — 195 (ADR-195, та же ветка).

## Контекст

ADR-195 завёл публичный контур: лендинг и четыре страницы о проекте, 29 языков, 145
адресов. Само по себе это ещё не делает их читаемыми снаружи.

Проверено на живом проде 29.10 (`curl -D-`):

- оболочка SPA — 2287 байт, один `og:description` на весь домен, и он был по-русски,
  хотя апекс теперь английский;
- `/robots.txt` и `/sitemap.xml` отвечали **200 с `content-type: text/html`** — то есть
  поисковик получал HTML вместо директив (файлов не было, `try_files` уводил в
  `index.html`, а правило 404 в `locations.conf` ловит только `.php/.env/.yml`).

Главный довод не про Google. Краулеры мессенджеров — Telegram, WhatsApp, VK — **не
исполняют JS вообще**. Для продукта, который распространяется ссылкой «посмотри, вот
через что мы оформим сделку», это значит, что КАЖДАЯ расшаренная ссылка показывает
одинаковую пустую карточку. Google-то SPA отрендерит, но новый домен индексирует
неохотно, а 29 языковых версий без отдельных HTML для него не существуют.

Владелец выбрал вариант «сразу с prerender», а не «SPA сейчас, HTML потом».

## Решение

### A. Сборка в три шага, шаблон — результат клиентской сборки

```
vite build                → dist/ (оболочка + бандлы с хешами)
vite build --ssr …        → dist-ssr/entry-prerender.js
node scripts/prerender.mjs → 145 html + sitemap.xml в dist/
```

Шаблон для всех 145 файлов — **сам `dist/index.html`**, а не отдельная заготовка: в нём
уже стоят ссылки на бандлы с хешами содержимого. Своя заготовка разъехалась бы с
бандлами на первой же сборке, и страницы молча остались бы без JS и CSS.

SSR-точка (`web/src/entry-prerender.tsx`) рисует те же компоненты через `StaticRouter` +
`useRoutes(publicRoutes())` — тот же реестр маршрутов, что в браузере. Языковой пакет
грузится тем же `loadLocaleResources`, что и в рантайме, и ДО `changeLanguage`: 27 из 29
языков лежат ленивыми чанками, и без загрузки пререндер выдал бы 29 английских копий.

В SSR-точке нет `QueryClientProvider`, мока и service worker'а. Это не упрощение, а
проверка инварианта: публичные страницы обязаны рисоваться из бандла без единого запроса
к бэкенду. Появится на публичной странице хук с запросом — сборка упадёт здесь, в
понятном месте.

### B. Лендинг — отдельный файл `landing.html`, а не пререндер в `index.html`

nginx: `location = /` → `try_files /landing.html /index.html`.

Почему не писать лендинг прямо в `index.html`: это оболочка для ВСЕХ клиентских
маршрутов (`try_files $uri $uri/ /index.html`), и текст лендинга внутри неё на долю
секунды видел бы каждый залогиненный человек, открывающий `/contracts/123`. Разные
задачи — разные файлы. Фолбэк на `index.html` оставлен сознательно: если пререндер не
отработал (dev-образ, правка пайплайна), сайт остаётся рабочим — SPA нарисует тот же
лендинг клиентским роутингом, просто без готового HTML для краулера.

Остальные страницы ложатся как `dist/<путь>/index.html` и попадают к человеку
внутренним редиректом от `try_files $uri/` — правок nginx для них не нужно.

### C. Мерцание у тех, кому лендинг не предназначен

nginx отдаёт `landing.html` всем — он не знает, кто пришёл. Залогиненный и установленное
приложение получат тот же файл и до монтирования SPA видели бы маркетинговый текст.

Решение «что показать» остаётся в React (`ShellOrLanding`, ADR-195) — в одном месте и под
тестом. В HTML добавлен только инлайн-скрипт на 8 строк, который прячет статику, если в
`localStorage` есть сессия (`porukam.auth`) или в адресе стоит `?src=pwa`/`?src=twa`
(ADR-176). React при первом рендере контейнер всё равно вычищает; скрипт убирает именно
мерцание. Всё в `try/catch`: приватный режим не должен ломать страницу.

### D. Кэш и service worker — две правки, без которых это тихо не работает

1. **`globIgnores` workbox.** 145 файлов подходят под `globPatterns: **/*.html` и уехали
   бы в precache установленного приложения — почти полмегабайта маркетинговых страниц,
   которые приложению не нужны (те же страницы оно рисует клиентским роутингом). Маска
   `**/*/*.html` отсекает только вложенные файлы, корневой `index.html` (оболочка) в
   precache остаётся.
2. **`Cache-Control: no-cache` на публичные HTML** (`location ~ \.html$`). Перед нами
   Cloudflare; устаревшая страница на edge означает устаревшие тексты и устаревшие
   og-теги после деплоя. Та же причина, по которой no-cache уже стоит у `index.html`,
   `sw.js` и манифеста.

### E. Мета печатается из тех же строк, что видит человек

`features/publicSite/meta.ts` — одна функция `publicMeta(t, slug)` на два применения:
эффект в браузере (`usePublicMeta`) и статический `<title>`/`description` при сборке.
Отдельных строк «для поисковика» нет: заголовок страницы и первый абзац её текста — ровно
то, что должно стоять в выдаче. Два разных текста разошлись бы.

В `<head>` каждой страницы печатаются `canonical`, `og:url`, `og:locale`, `og:description`
на языке страницы и **29 `hreflang`-альтернатив + `x-default`** на апекс. Поэтому
`sitemap.xml` остаётся плоским списком адресов: вести те же соответствия вторым списком
значило бы гарантированно получить расхождение.

Скрипт проверяет результат, а не верит в него: пустой рендер, отсутствие заголовка или
описания, непопадание описания в HTML, невставленная разметка — каждое роняет сборку с
названием адреса. `og:description` в шаблоне записан prettier'ом в несколько строк, и
регулярная замена по нему — ровно то место, где молчаливый промах был бы вероятен.

## Последствия

- `npm run build` стал трёхшаговым и длиннее (145 рендеров). Docker-образ собирает тем
  же скриптом, отдельного шага в пайплайне не появилось.
- `dist-ssr/` — новый артефакт сборки (уже в `.gitignore`), в образ не попадает.
- Добавление языка или страницы автоматически добавляет файлы: список один —
  `allPublicPaths()`.

## Пределы задачи

- **JSON-LD** (`Organization`, `FAQPage`) не добавлялся: это следующий шаг по
  SEO и он не связан с механикой пререндера.
- **`og:image` на страницу** остаётся общим баннером домена; отдельные картинки под
  языки/страницы — отдельная задача (и отдельная раскадровка, см. пределы ADR-195).
- **Проверка в бою** возможна только после деплоя: `nginx -t` на образе, затем
  `curl -I https://porukam.app/robots.txt` (ожидается `text/plain`), `curl -s
  https://porukam.app/ | head` (ожидается текст лендинга), и прогон ссылки через
  отладчик превью Telegram.
