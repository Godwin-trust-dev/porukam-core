# ADR-105. Формы существа Аренды и Займа — по схеме бэка

Дата: 2026-08-21. Статус: принято.
Ветка: `feat/web-forms-rent-loan` (UI; бэк без изменений).

## Контекст

Мастер договора имел ручные формы существа только для Услуги
(`ServiceEssence`) и Продажи (`SaleEssence`). Аренда → вещи / жильё и Займ
показывали «Форма существа для этого типа договора ещё не подключена», а
превью блокировало отправку (решение «В без отправки пустых»). На бэке при
этом давно есть полные схемы (`apps.contracts.forms`: `RENT_ITEMS_SCHEMA`,
`RENT_HOME_SCHEMA`, `LOAN_SCHEMA`, П-16) и `GET /contract-types/{code}/form-schema`
(`serialize_schema`: секции → поля с типом, обязательностью, вариантами,
условием видимости, ключом подсказки). Отсмотр 2026-08-21: «по аренде то же
самое, что было по продажам… надо ремонтировать».

## Решение

Один рендерер по схеме вместо трёх ручных форм:

- `web/src/features/contractNew/formSchema.ts` — типы DTO, `useFormSchema`,
  условная видимость (`condition: {field, in}`), гейт «Далее»
  (`schemaComplete`), приведение значений к контракту бэка
  (`buildSchemaFormData`: decimal → строка, integer → number, list_str →
  массив строк по запятым/строкам, `schedule` → `[{due_date, amount}]`) и
  обратно (`valuesFromFormData`), сумма единственного листа
  (`schemaStageAmount`).
- `web/src/pages/contract-new/SchemaDetailsForm.tsx` — секции → поля по
  типу; валюта — рядом с первым денежным полем; способ оплаты — в конце
  (как у продажи). `list`-поля, кроме графика займа (инвентарь, показания
  счётчиков), в этой волне не показываются — они необязательны.
- `DetailsStepPage`: как у Продажи, шагов «Этапы»/«Условия» нет — шаг держит
  ОДИН лист: аренда — плата за период, займ — тело + проценты (или сумма
  графика). Так `freeze` получает дерево с `total_leaf_amount`.
- `PreviewStepPage`: сводка существа по ключевым полям схемы, гейт
  «есть существо» — по схеме (`schemaHasEssence`).
- Подписи — `contractNew.schemaForm.<схема>.{section,field,choice,<hint>}`:
  ключи секций/подсказок бэка (`contract_forms.*`) отображаются префиксом
  (`mapBackendI18nKey`), поля и варианты — по ключу поля. Бэк ключей для
  подписей полей не отдаёт — и не должен: тексты живут в пакете i18n.
  ru/en — вручную; 30 ленивых локалей получили EN-копию (паритет ключей
  `localePacks.test.ts` соблюдён), бэкфилл переводов — отдельным чором, как
  для #94/95.

Услуга и Продажа остаются ручными формами: у них есть побочные сущности
(сфера/тип работ, лист «передача товара», доставка) и своя раскладка;
переводить их на рендерер — отдельное решение.

## Последствия

- Новый тип договора с серверной схемой подключается без кода формы:
  достаточно добавить подписи в `contractNew.schemaForm.<схема>`.
- `list`-поля с произвольной структурой (инвентарь, счётчики) потребуют
  своих редакторов, когда станут обязательными.
- Узкое место — один лист-этап на аренду/займ; график платежей займа как
  дерево этапов (`POST …/milestones/loan-schedule`) — следующий шаг.
