# ADR-165. Вход только по аккаунту Google на публикацию: `PHONE_LOGIN_ENABLED`

**Статус:** принято (решение владельца 2026-09-05)
**Контекст:** apps.accounts (`api/views.py` — `auth/otp/request`, `auth/otp/verify`),
`config/settings/base.py`, `прод-конфиг`, `прод-конфиг`
**Номер:** 165 — следующий свободный по сканированию `docs/adr/` во ВСЕХ ворктри
(максимум на 05.09 — 164). Строка добавлена в индекс README.

## Контекст

Решение владельца 05.09 к публикации приложения: «вход только по аккаунту Google, остальное
прячем».

Фронт эту половину уже закрыл: прод-образ SPA собирается с `VITE_PHONE_LOGIN_ENABLED=0`
(`конфиг nginx`, `web/src/features/auth/phoneLoginFlag.ts`) — формы входа по
телефону в интерфейсе нет.

Бэкенд при этом остался прежним:

- `POST /v1/auth/otp/request` и `POST /v1/auth/otp/verify` вызываются напрямую — спрятанная
  кнопка эндпоинт не закрывает;
- SMS отправляет `FakeSMSGateway` (реального гейтвея в проекте нет вовсе), то есть при
  включённом OTP-контуре код никуда не доставляется, и единственный способ им
  воспользоваться — общий фиксированный код;
- `OTP_FIXED_CODE` (`settings/base.py`) как раз и делает код общим: любой знающий его входит
  под ЛЮБЫМ номером, а `auth/otp/request` ещё и возвращает его в `dev_hint`. В прод-compose
  переменная сейчас не пробрасывается (дефолт `None`), но одна строка в прод-`.env` — и вход
  открыт для всех.

Пока Google OAuth был закрыт списком тестовых пользователей, риск был ограничен. На публикацию
список снимается — остаётся дыра: закрытый в интерфейсе способ входа, живой в API и способный
пустить кого угодно.

## Решение

1. Настройка `PHONE_LOGIN_ENABLED` (`config/settings/base.py`, `env.bool`, дефолт `True`).
   Дефолт именно `True`: dev-стенды и тесты входят через OTP, и менять их поведение эта ветка
   не должна. Прод выключает вход явно — `PHONE_LOGIN_ENABLED=false` в `прод-конфиг`.
2. При выключенном флаге OTP-эндпоинты отвечают `403` c кодом `phone_login_disabled` в
   `application/problem+json` (tech-spec.md §7.5). Проверка — во вьюхе (`_PhoneLoginView.initial`
   в `apps/accounts/api/views.py`), не в сериализаторе: она про способ входа, а не про данные
   запроса, и должна срабатывать до `services.request_otp` (при выключенном входе SMS не
   отправляется и код в кеше не заводится, rate-limit не греется). Не `BasePermission` — тот
   умеет только обобщённый `permission_denied`, а фронту нужен различимый код, иначе «вход
   отключён» не отличить от протухшей сессии.
3. Google-контур (`auth/google/authorize-url`, `auth/google/callback`) не трогается — это
   единственный способ входа на публикацию.
4. Привязка телефона к УЖЕ вошедшему аккаунту (`PATCH /v1/users/me`, поле `phone`) остаётся
   разрешённой: она требует access-токена, не выдаёт токенов и войти по ней нельзя. Флаг
   закрывает вход, а не наличие телефона в профиле (телефон нужен договорам и уведомлениям).
5. `OTP_FIXED_CODE` при деплое из прод-`.env` убирается: флаг и общий код — независимые
   рычаги, и общий код не должен пережить обратное включение входа по недосмотру.
6. Прод-compose пробрасывает env ЯВНЫМ списком, поэтому `PHONE_LOGIN_ENABLED` добавлен в блоки
   `core`, `celery_worker` и `celery_beat`. Дефолт там — `${PHONE_LOGIN_ENABLED:-false}`,
   СТРОЖЕ дефолта настроек: прод-compose локально без `.env` никто не запускает, а молча
   уехать на открытом дефолте прод не должен (правило проекта). Без этих строк прод поехал бы
   на `True` — тот же класс инцидента, что Web Push/Resend и Э6. Дефолт `True` остаётся только
   в `settings/base.py`, где он обслуживает dev-стенды, тесты и локальный compose.

## Последствия

- Публичный контур имеет ровно один вход — аккаунт Google. Обратное включение — одна
  переменная окружения и перезапуск `core`+`celery`, кода это не касается.
- Пользователь, случайно попавший на `/login` со старой ссылкой или из закешированного SPA,
  получает различимый код ошибки `phone_login_disabled`, а не «нет прав».
- OTP-код и все его тесты остаются в репозитории: способ входа выключен, а не удалён — когда
  появится реальный SMS-гейтвей, включение будет переменной окружения.
- Локальные и CI-стенды не меняются (дефолт `True`).
- EN-заголовок ошибки добавлен в `common/api/error_texts.py`; для остальных языков работает
  штатный фолбэк пакета языка → EN-реестр (ADR-077).

## Чек-лист деплоя

1. В прод-`.env` (`прод-конфиг` на ВМ): добавить `PHONE_LOGIN_ENABLED=false`.
2. Там же: убедиться, что `OTP_FIXED_CODE` отсутствует (или удалить строку).
3. Перезапустить `core`, `celery_worker`, `celery_beat` (переменные читаются на старте).
4. Проверить на проде: `POST /v1/auth/otp/request` → `403`, `code: phone_login_disabled`;
   вход через Google работает.
