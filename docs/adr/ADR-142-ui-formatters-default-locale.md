# ADR-142. Локаль форматтеров по умолчанию синхронизируется с языком интерфейса

**Статус:** принято (замечание тестеров 2026-08-27)
**Контекст:** packages/core (format.ts), packages/ui (29 компонентов), web/src/app/providers.tsx; уточняет DEV-16 §5

## Контекст

Контракт DEV-16 §5 («единственная точка форматирования — хелперы core с явной `locale`»)
исполняется только страницами web через `useFormatters()`. Компоненты дизайн-системы
`packages/ui` (29 файлов: `SignatureRow`, `PartyRow`, `Card`, `StageRow`, `MoneyBreakdown`,
`ContractPassport` и др.) зовут `formatMoney`/`formatDateTime` из core напрямую без
аргумента `locale` — и молча получали захардкоженный `DEFAULT_LOCALE = 'ru-RU'`.
Итог на проде: даты подписания «27 авг. 14:05» и русская группировка разрядов сумм
при любом языке интерфейса (замечание тестеров 27.08: «дата и время отражаются в
российском стандарте»).

## Решение

`DEFAULT_LOCALE` в `packages/core/src/format.ts` становится изменяемым модульным
значением: экспортируется `setDefaultFormatLocale(locale)`. Приложение синхронизирует
его с i18n в одном месте — `web/src/app/providers.tsx`, рядом с существующей
синхронизацией `setActiveLocale` (init + `i18n.on('languageChanged', …)`).

Почему так, а не React-контекст в `packages/ui`:

- правка в 2 файлах против механической правки всех 29 компонентов и их call-sites;
- перерисовка при смене языка уже гарантирована i18next-ре-рендером (все компоненты
  получают переведённые строки через пропсы) — реактивность контекста ничего не добавляет;
- дефолт `'ru-RU'` сохраняется для не-React контекстов (юнит-тесты, скрипты, Storybook) —
  их поведение не меняется.

`useFormatters()` остаётся каноном для web-кода: он передаёт локаль явно и не зависит
от этого дефолта.

## Последствия

- Даты/суммы в ui-компонентах следуют языку интерфейса; `numberingSystem: 'latn'` и
  LTR-островки (DEV-16 §5, DEV-16c §2) не затронуты — они выставляются внутри хелперов.
- Таймзона по-прежнему `Europe/Moscow` (`DEFAULT_TZ`) — отображение TZ пользователя
  остаётся отдельным решением (не входит в этот ADR).
- Новый код в `packages/ui` может по-прежнему звать хелперы без `locale` — это теперь
  корректно по построению.
