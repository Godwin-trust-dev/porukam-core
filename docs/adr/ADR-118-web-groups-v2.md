# ADR-118: Объединения v2 в web — форма с подсказками из книги, публичная карточка, объединения в шапке

Дата: 2026-08-24. Статус: принят. Фаза 3 ADR-117 (бэк влит PR #216).

## Контекст

ADR-117 дал бэку типы из книги (гильдия/клан/сообщество/витрина), обязательную сферу,
географию, ссылки, обязательный хендл при создании, логотип, публичный (анонимный) просмотр и
блок `groups` на карточке репутации. Фронт v1 (`GroupsPage`/`GroupDetailPage`, отсмотр
2026-08-23) знал только `kind` v1, создавал объединение без хендла (после деплоя бэка — 400)
и не умел ни карточки для гостя, ни настроек. Открытым остался вопрос «ActorSwitcher лидера».

## Решения

### 1. Одна форма витрины — `features/groups/GroupForm`

Поля ADR-117 §§1–4 в одном компоненте для создания (модалка `GroupsPage`) и настроек
(модалка `GroupDetailPage`, `PATCH /groups/{id}`). Тип — `SelectField` с подсказкой «?»
(`FieldHelp`) — текст из книги для выбранного типа, 29 локалей. Сфера — `SpherePicker` и
`useSpheres` мастера договора (тот же каталог, `sphere_code` по значению). География —
`geo_scope` + страна (`Intl.DisplayNames`, список ISO-кодов `COUNTRY_CODES` — нативная
локализация имён стран без 29 словарей) + город. Ссылки — до 10 строк url/label.
Клиентская валидация повторяет инварианты бэка (`validateGroupForm`: имя, сфера, гео);
серверные коды `handle_taken`/`invalid_handle`/`invalid_sphere`/`invalid_geo` — к полям.

### 2. Хендл — обязателен при создании (`HandleField`), смена — в настройках

В модалке создания `HandleField` (без сетевой проверки занятости — эндпоинта для групп нет,
как и для людей после fix/web-handle-check-real; занятость решает `409 handle_taken`).
Отдельная кнопка «Сохранить хендл» после создания убрана — осталась «Сменить хендл» в
панели лидера (`POST /groups/{id}/handle`).

### 3. Публичная карточка — `features/groups/GroupCard`, два входа

Одна вёрстка (логотип, имя, @хендл с копированием, тип/вход/закрытость, сфера или бейдж
«не указана», география, участники/дата создания/лидер, описание, ссылки, список участников
с переходом в карточки репутации): `/groups/{id}` в оболочке (действия участника + панели
лидера) и гостевой `/@хендл` (`ReputationCardPage` → `GroupPublicPage`, когда
`GET /handles/{h}` отдаёт `group_id`; без него — прежняя заглушка «карточки нет»).
Запросы чтения групп больше не гейтятся `isAuthenticated` — бэк `AllowAny`.

### 4. «Состоит в объединениях» на личной карточке

Блок над сделками, виден и при `restricted` (ADR-117 §7); пилюли ведут на `/@хендл`
объединения (или `/groups/{id}` без хендла).

### 5. Объединения в ActorSwitcher — НЕ актёры

Объединение не сторона договора и не носит репутацию (tech-spec §5.2.1b) — оно не может
быть `X-Acting-Profile`. Поэтому в меню шапки добавлена секция «Мои объединения» (лидер/
админ): выбор строки только открывает карточку объединения, актёр не меняется, строка
не помечается «активной». Источник — `GET /groups` c `my_membership`; закрытые (`is_public
=false`) в публичном списке отсутствуют — к ним лидер идёт по ссылке. Отдельный эндпоинт
«мои членства» не вводится: два экрана (шапка, «Мои объединения» на `/groups`) закрываются
имеющимся списком.

### 6. Что НЕ вошло

- География **личного** профиля («весь мир») — у `Profile` нет `geo_scope`; есть
  `works_remotely` (= «работаю удалённо»). Отдельная задача бэка `feat/profiles`, если
  понадобится.
- Портфолио объединения, коллективная репутация — ADR-117 §«Подумать ещё», не здесь.
- Учёт географии объединений в зонах `/search` — вместе с «поиском по сферам» (ADR-114 v2).

## Последствия

- Деплой только после merge этого PR (бэк уже в main): создание объединения без хендла — 400.
- `Group.kind` в `@porukam/core` — коды v2; ключ `dashboard.groupKindInformal` удалён из 29
  локалей, добавлены 51+2 ключа (`dashboard.group*`, `reputation.groupsTitle`,
  `shell.actorSwitcher.groups`).
- Мок `groupsHandlers` зеркалит v2 (публичное чтение, 404 для приватного гостю, PATCH, логотип,
  занятость хендла) и отдаёт `group_id` в `GET /handles/{h}` и `groups` в карточку.
