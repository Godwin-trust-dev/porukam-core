# ADR-102. Мета пункта ленты уведомлений — из живого договора при чтении

Дата: 2026-08-20. Статус: принято. Уточняет ADR-098.
Ветка: `feat/notifications-feed-live-enrichment`.

## Контекст

ADR-098 сделал уведомления кликабельными: в момент размещения
`place_notification` дописывал в payload `contract_title/number`,
`counterparty_*`, `amount/currency` и заполнял колонку `contract_id`;
лента (`selectors._feed_item`) читала только это.

Отсмотр прода 2026-08-20 (`/notifications?sel=01a01a76-…`): уведомление
«Договор отправлен на согласование» от 19.08 — без ссылки, без контрагента,
без суммы. Причины:

1. Записи, размещённые **до** выката ADR-098/#143, обогащения не получили
   и не получат никогда: payload append-only (`content_hash` — юрзначимый
   слепок), миграции-бэкфилла нет и быть не должно.
2. `amount` вообще не доходил до фронта: `_feed_item` его клал, а
   `NotificationFeedItemSerializer` поля не объявлял — DRF молча выкидывал.
3. Снимок суммы на момент события расходится с текущей суммой договора
   (до заморозки этапы правятся).

## Решение

- Мета пункта (ссылка, название/номер договора, контрагент относительно
  получателя, сумма) резолвится **при чтении ленты** из текущего состояния
  договора: `selectors.feed_contract_contexts()` → `FeedContractContext`.
  Договор ищется по колонке `contract_id`, иначе по `payload.contract_id`,
  иначе по `payload.milestone_id` → договор этапа. Одним батчем на ленту
  (`contracts.selectors.list_contracts_by_ids` со сторонами;
  `resolve_counterparty` использует prefetch).
- Живой договор **приоритетнее** payload (ни один издатель событий эти
  ключи сам не кладёт — они только от обогащения). Payload — фолбэк для
  удалённого договора.
- Текст пункта рендерится с теми же подстановками: старые записи получают
  полную фразу «Договор «…» отправлен…» вместо короткой темы.
- Обогащение при размещении (ADR-098) **остаётся** — оно нужно для
  push/email/SMS, которые уходят в момент события, и как фолбэк.
- Сериализатор ленты объявляет `amount` (`{amount: строка Decimal,
  currency}`, пары нет — ключа нет).

## Последствия

- Любое уведомление по существующему договору кликабельно и с метой —
  независимо от даты размещения и версии кода, его создавшей.
- +2–3 запроса на ленту (договоры со сторонами, этапы для суммы, названия
  этапов) вместо 0; лента не пагинируется, размер — десятки записей. Если
  вырастет — кэш по `contract_id` в пределах запроса уже есть, дальше —
  пагинация (отдельное решение).
- `payload` и `content_hash` не меняются ни для одной записи.

## Тесты

`apps/notifications/tests/test_feed_live_context.py`: старая запись с
пустым payload → ссылка/контрагент/сумма/полный текст; contract_id только
в payload; milestone_id → договор и название этапа; живая сумма поверх
снимка; удалённый договор → фолбэк на payload; `amount` сквозь API.
