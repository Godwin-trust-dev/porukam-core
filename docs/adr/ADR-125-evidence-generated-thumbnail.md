# ADR-125: Миниатюра доказательства строится из очищенных байт, если камера не встроила превью

Дата: 2026-08-25. Статус: принят. Уточняет ГВ.3 п.2 (`services/evidence_ingest`).

## Контекст

Отсмотр прода 2026-08-25: «доказательство не загружено, а хеш создался. Клиент получает 3 хеша и
2 пустых образа». Разбор: файл загружен и захеширован, но миниатюра бралась ТОЛЬКО из встроенного
EXIF-превью JPEG (`jpeg.py`, «честно, без подделки»). У типичных фото с телефона его нет —
скриншоты, галерея Android (EXIF вырезан), HEIC→JPEG-конвертация браузером, PNG/WebP вообще без
EXIF. `GET /evidence/{id}/thumbnail` отвечал 404, просмотрщик показывал пустой экран — для человека
это выглядит как «файл не загрузился».

Отдельная причина «не подтягивает, 413» — nginx с дефолтным `client_max_body_size 1m` отбивал
фото до бэка (исправлено в `конфиг nginx`, 30m при лимите бэка 25 МБ).

## Решение

1. `pipeline.ingest`: если после JPEG-очистки встроенного превью нет — `generate_thumbnail(relay_bytes)`
   строит его Pillow из ТЕХ ЖЕ очищенных байт, что уходят в релей и под хеш: JPEG ≤ 320px по большей
   стороне, RGB, без метаданных. Форматы — JPEG/PNG/WebP/GIF/BMP/TIFF (декодируются Pillow без
   плагинов). HEIC/HEIF — без декодера, миниатюры нет; просмотрщик на фронте показывает «превью
   недоступно, файл сохранён» и кнопку скачивания оригинала.
2. Встроенное EXIF-превью камеры остаётся источником №1 — генерация только фолбэк.
3. Хеш и `relay_bytes` не меняются: миниатюра — производная от того же содержимого, не самостоятельное
   доказательство; принцип «не подделываем» сохраняется (ничего не дорисовывается, только уменьшается).
4. Не декодируемые байты (mime врёт) → `thumbnail=None`, приём не падает (честная деградация, как и
   прежде для «не-JPEG под видом JPEG»).

## Последствия

- Уже загруженные доказательства без превью не пересчитываются (append-only, ничего не трогаем);
  фронт показывает для них фолбэк с загрузкой оригинала.
- Тесты `services/evidence_ingest/tests/test_pipeline.py`: генерация для JPEG/PNG/WebP/RGBA, приоритет
  EXIF-превью, неизменность хеша, деградация для мусора и HEIC.
