# ADR-115. Портфолио: реальная фото-обложка проекта

Дата: 2026-08-23. Статус: принято.

## Контекст

Отсмотр 2026-08-23: «делаем портфолио работ». Модель и API портфолио УЖЕ
существуют (Portfolio/PortfolioProject, domain-model.md §3.4: проекты,
verified-факты из договоров, publish), но `media` — JSON ссылок/подписей без
реального байтового пайплайна, а фронтовый раздел /me/portfolio — заглушка.

## Решение

1. **Не новая модель, а `PortfolioProject.photo_key`** — одна фото-обложка
   на проект v1 (галерея на проект — расширение той же схемы позже).
   Дубль-модель «PortfolioItem» рассмотрена и отклонена: §3.4 уже описывает
   портфолио проектами, вторая витрина рядом — рассинхрон.
2. **Пайплайн — переиспользование аватарного** (ADR-103): та же санитария
   (EXIF в пиксели и прочь, первый кадр, decompression-bomb-порог), то же
   S3-хранилище и Fake для тестов; отличие — БЕЗ квадратного кропа
   (`images.process_portfolio_image`), варианты WebP 1280 (просмотр) и
   320 (сетка), ключ `portfolio/<profile_id>/<uuid7>`.
3. **API**: `POST/DELETE /v1/portfolio/projects/{id}/photo` — владелец/
   представитель (manage_profile); `GET .../photo?size=1280|320` — AllowAny
   (портфолио — публичная витрина; человек сам публикует работы), Cache
   долгий, URL версионирован `?v=`. `photo_url` добавлен в
   PortfolioProjectSerializer.
4. Лимит файла — `PROFILE_PORTFOLIO_MAX_UPLOAD_BYTES` (10 МБ, env).

## Последствия

- Фронт: /me/portfolio перестаёт быть заглушкой (список проектов + загрузка
  обложки), витрина проектов с фото — на репутационной карточке.
- Замена обложки удаляет старые объекты после записи новых (как set_avatar).
