# ADR-109. Разделы «Этапы» и «Платежи» — кросс-договорные агрегаты в apps.dashboards

Дата: 2026-08-23. Статус: принято.

## Контекст

Отсмотр 2026-08-22: разделы `/stages`, `/payments`, `/disputes`, `/reputation`
надо делать (до этого — заглушки `SectionEmptyPage`). Для `/disputes` и
`/reputation` бэкенд уже есть (`GET /v1/disputes`, `GET /v1/reputation/
profiles/{id}/card`). Для `/stages` и `/payments` кросс-договорного среза не
было: `apps.milestones` отдаёт этапы только в рамках одного договора, а
`apps.payments` — заглушка каркаса (финмодель v2: платёжного контура нет,
деньги идут вне платформы, платформа наблюдает двусторонние
подтверждения-заглушки, tech-spec.md §6.3).

## Решение

1. Оба агрегата живут в `apps.dashboards` — по прецеденту ADR-090 это место
   read-only кросс-договорных срезов («только selectors поверх остальных»).
   НЕ в `apps.milestones` (его api — контур одного договора) и НЕ в
   `apps.payments` (появится с реальным платёжным контуром, Э5).
2. `GET /v1/dashboard/stages` — все ЛИСТЬЯ (domain-model.md §7.1) договоров
   в исполнении (`negotiation_status=signed`), где вызывающий — любая
   сторона; сортировка по дедлайну (без дедлайна — в конце). Новый селектор
   `apps.milestones.selectors.list_execution_leaves_for_profiles` — рядом с
   attention-селекторами ADR-090, но без фиксации роли.
3. `GET /v1/dashboard/payments` — денежные листья тех же договоров с
   выведенным на бэке состоянием `state`:
   `paid` (status=PAID либо обе отметки `paid_confirmed_*`) →
   `awaiting_confirmation` (ACCEPTED без обеих отметок) → `upcoming`
   (остальное). Плюс `paid_confirmed_by_me/by_counterparty` относительно
   стороны вызывающего — фронт не повторяет доменную логику.
4. Деньги — строкой + валюта, без валюты по умолчанию (CLAUDE.md); суммы по
   валютам НЕ агрегируются на бэке — считает фронт через `Money` (не
   складывает разные валюты по построению).
5. Контрагент в строках — `{profile_id, display_name}`;
   `display_name = null` при `show_name=false` (ADR-059) — ссылка на
   репутационную карточку строится по `profile_id`.

## Отклонено

- Отдельный `GET /v1/milestones?scope=mine` в `apps.milestones` — ломает
  симметрию ADR-090 (кросс-договорные срезы уже собраны в dashboards).
- Агрегирование сумм по валютам на бэке — дублирует `Money` фронта и
  раздувает контракт ответа.
- Пагинация — на запуске объёмы малы (единицы договоров на пользователя);
  добавится при необходимости без слома формы ответа.

## Последствия

- Фронт `/stages` и `/payments` — тонкие страницы поверх двух эндпоинтов.
- `/feed` решён отдельно (редирект на `/notifications` — см. бэклог),
  `/disputes`, `/reputation` — на существующих эндпоинтах, бэкенд не менялся.
