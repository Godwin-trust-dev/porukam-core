# ADR-111. Email-канал через Resend

Дата: 2026-08-23. Статус: принято.

## Контекст

Решение 2026-08-23: «email пока не делаем, если пуш взлетит» — отменено тем же
днём («сразу делай email, у нас есть Resend»). Email — дублирующий канал
(юрканал — ЛК, ADR-057); до сих пор работал FakeEmailProvider (ЭФ.4).
В прод-инфраструктуре есть аккаунт Resend (HTTP API отправки почты) — SMTP
(django.core.mail) не нужен.

## Решение

1. **`ResendEmailProvider`** реализует существующий `EmailProvider`-протокол:
   `POST https://api.resend.com/emails` через httpx (уже в зависимостях,
   ADR-084), text-only. HTML-вёрстка писем — отдельная волна, не блокер.
2. **Содержимое письма** — subject/body шаблона на языке получателя
   (render_subject/render_body, ADR-095) БЕЗ подстановок: сумм, имён и
   номеров договоров в письме нет — симметрично Web Push (ADR-110 §4).
   Детали человек смотрит в ЛК по прежней логике.
3. **Выбор провайдера** — env `NOTIFICATIONS_EMAIL_PROVIDER=resend|fake`
   (дефолт fake), резолв на вызов `place_notification` — симметрично
   `NOTIFICATIONS_PUSH_PROVIDER` (ADR-110 §3).
4. **Деградация без падения**: сеть/4xx/5xx → `delivered=False` +
   `circuit.record_failure`; размещение в ЛК уже состоялось, юрканал не
   зависит от Resend. `email_sent_at` не ставится — метрика недоставки видит.
5. **Конфигурация**: `RESEND_API_KEY` (секрет, только prod `.env`),
   `NOTIFICATIONS_EMAIL_FROM` — адрес на домене, верифицированном в Resend
   (DKIM/SPF-записи в DNS зоны porukam.app — шаг включения на проде).
6. **OTP по email** — вне скоупа этого ADR (отдельная точка в apps.accounts,
   бэклог).

## Отклонено

- SMTP (`django.core.mail` + EMAIL_HOST*) — план до появления Resend;
  переменные EMAIL_* остаются в .env.example как исторический задел, код
  их не использует.
- Библиотека-SDK resend — один POST-запрос не оправдывает зависимость,
  httpx уже есть.
- HTML-шаблоны писем — следующая волна (вместе с брендингом писем).

## Последствия

- Прод: получить API-ключ в resend.com, верифицировать домен porukam.app
  (DNS-записи в Cloudflare), три переменные в `.env`, рестарт core.
- Пользовательская настройка «Email» в уведомлениях начинает реально
  работать (была честной заглушкой).
