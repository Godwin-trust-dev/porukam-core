# ADR-143. Окна (`Modal`, `Sheet`) рендерятся порталом в `document.body`

**Статус:** принято (баг тестера 2026-08-31, `docs/tasks/screenshots_bugs/bug_01_sdelki.png`)
**Контекст:** packages/ui (`Modal.tsx`, `Sheet.tsx`, `ContractListRow.module.css`),
packages/ui/src/layout (`MasterDetail.module.css`); уточняет DEV-09 §4.3/§9 (окна) и DEV-19 §2 (master-detail)

## Контекст

Оба окна дизайн-системы рендерились на месте вызова и полагались на
`position: fixed; inset: 0; z-index: 100`. Это работает ровно до тех пор, пока ни у
одного предка нет `contain`, `transform`, `filter`, `backdrop-filter`, `perspective`
или `will-change` по ним: любое из этих свойств делает предка содержащим блоком для
`fixed`-потомков и создаёт контекст наложения, внутри которого `z-index: 100` уже
ничего не значит снаружи.

Наступили на это в списке сделок. Строка `ContractListRow` объявляет
`container-type: inline-size` (введено 21.08, чтобы строка верстала себя по ширине
КОЛОНКИ master-detail, а не окна) — а `container-type` включает `contain: layout`.
Окно «Действия» (`Sheet`) живёт внутри строки, поэтому:

- его подложка перестала быть на весь вьюпорт и обрывалась по границам рабочей области;
- весь контекст строки рисуется ниже соседней колонки деталей
  (`.detail { position: sticky }` — позиционированный элемент), и текст пустого
  состояния «Выберите договор» лёг поверх окна;
- крестик закрытия оказался под этим текстом и перестал нажиматься — окно нельзя
  было закрыть иначе как Escape или кликом по подложке.

Жалоба владельца звучала как две разные («текст поверх окна» и «крестик не работает»),
но причина одна.

## Решение

`Modal` и `Sheet` рендерятся через `createPortal(…, document.body)`.

Почему портал, а не подъём `z-index`:

- `z-index` лечит симптом в одном месте и ломается снова от любого нового предка
  с `contain`/`transform`/`filter` — а `container-type` мы будем ставить и дальше,
  это правильный инструмент для адаптива по контейнеру (он уже стоит в
  `PaymentPlan.module.css` и `GroupsPage.module.css`);
- портал снимает зависимость от вёрстки предков полностью и навсегда;
- React-контекст через портал проходит, поэтому i18n, роутер и query-клиент внутри
  окон продолжают работать без изменений; DOM-события всплывают по React-дереву,
  а не по DOM — существующие `onClick`-обёртки со `stopPropagation` не ломаются.

Цена: содержимое окна больше не находится в поддереве вызвавшего компонента. Тесты,
которые искали окно через `container.querySelector`, пришлось бы править — на момент
решения таких не оказалось (весь набор 808 тестов зелёный без правок).

## Последствия

- Правило дизайн-системы: **любое перекрывающее окно рендерится порталом**. Новый
  оверлей, добавленный по образцу существующих, наследует это автоматически.
- Закреплено тестом `web/tests/OverlayPortal.test.tsx`: окно не остаётся в поддереве
  вызвавшего компонента, и крестик закрывает окно из-под предка с `contain: layout`.
  Проверять «правильный z-index» бессмысленно — jsdom не считает раскладку.
- `container-type: inline-size` остаётся разрешённым приёмом: после портала он больше
  не конфликтует с окнами.
