# ADR-152. Шапка телефона принадлежит экрану; списки во всю ширину; три вкладки «Сделок»

**Статус:** принято (замечание владельца 03.09 по эталонам
`marketing/reference/front-upgrade/ref15_finalA_1.png` — финал доска A,
`ref17_desktopFinal.png` — compact-десктоп; решение владельца 03.09 по вкладкам «Сделок»)
**Контекст:** развивает ADR-146 (density-слой) и ADR-149 (строка v2, две вкладки, жесты).
Затронуты `packages/ui` (`Surface`, `ScreenHeader`, `ScreenTabs`, `Button`, `Avatar`,
`AttentionCard`, `SettingRow`, `PushPromo`, `SummaryCard`, `SectionLabel`, токены),
`web/src/features/shell/shellHeader.tsx`, экраны Главная/Сделки/Уведомления/Чат/Профиль/Настройки

## Контекст

Отсмотр владельца по финальным доскам: «есть оранжевый плюсик вместо кнопки добавить;
в профиле большой баннер под описанием — лишний; нет рамки в договорах и на главной,
из-за этого места больше и текста больше; проверь цвета, рамки, тексты по каждому
экрану; должно быть как на картинках». Сравнение скриншотов с досками дало четыре
структурных расхождения, которые нельзя закрыть точечной вёрсткой:

1. На телефоне у каждого экрана была **своя шапка под шапкой оболочки** — название
   стояло дважды («Уведомления ˅» и ниже «Уведомления»), а действия («Прочитать все»,
   «Начать переговоры») занимали ещё одну полосу. На доске действие стоит в одной
   строке с названием, а у настроек вместо меню разделов — «‹ Настройки».
2. Списки стояли в **карточке с рамкой и отступами**; на доске список — белая
   плоскость **во всю ширину** телефона, разделённая hairline.
3. Под шапкой профиля стоял **баннер** «важное уведомление» (`NextStepSlot`), которого
   на доске нет.
4. «Сделки» с двумя вкладками (ADR-149 §2) прятали черновики в воронку — владелец:
   «черновики сложно найти, нужно в фильтр заходить».

## Решение

### 1. Слоты шапки оболочки — порталом, а не состоянием

`ShellHeaderHost` (в `ShellLayout`) держит два пустых контейнера — заголовок и действия —
и отдаёт их через контекст. Экран вызывает `useShellHeader({ title?, actions? })` и
получает `portal` (рендерит у себя) и `inShell` (передаёт в `ScreenHeader`, который на
`<1024` прячется). Пока экран ничего не занял, оболочка показывает меню разделов и
переключатель актёра; заняв — прячет соответствующую половину.

Почему портал, а не `setState(actions)`: узел действий пересоздаётся каждый рендер
экрана, и хранение его в состоянии провайдера даёт петлю «рендер → setState → рендер».
В состоянии остаются только два булевых флага «занято»; сами узлы уезжают порталом.

Без провайдера (изолированный рендер экрана в тестах) хук возвращает `inShell: false`,
и экран рисует свою шапку сам — тесты страниц не зависят от оболочки. На десктопе
слоты оболочки спрятаны CSS, работает `ScreenHeader` экрана; Playwright `getByRole`
не видит `display: none`, поэтому дублей в проверках нет.

### 2. `Surface bleed` — список во всю ширину телефона

Опция, не глобальное поведение: доска B показывает детальные экраны с паддингом и
рамками, во всю ширину там только список этапов. `bleed` на `<1024` снимает рамку и
радиус, выходит отрицательным `margin-inline` за паддинг контента оболочки и рисует
hairline сверху и снизу. На десктопе — обычная поверхность с рамкой (compact-десктоп).
Применено к спискам Главной, Сделок, Уведомлений, Чата, меню профиля, хабу настроек.

### 3. Профиль без баннера; действия под карточкой

`NextStepSlot` с экрана `/me` убран (компонент и ключи остаются): важное живёт в ленте,
счётчик — на плитке «Уведомл.». `PassportHeader` принимает `actions={null}` — ряд
«Редактировать · Как гость · поделиться» стоит под карточкой, как на доске. Карточка
«Репутация на фактах» убрана (дублировала «Как гость»). Меню — строки со значками.

### 4. «Сделки»: три вкладки — решение владельца перекрывает ADR-149 §2 для этого экрана

`Активные · Черновики · Архив` (`ScreenTabs allowExtra`); в воронке остаются роль,
сортировка и «Все» (плюс текущая вкладка, чтобы селект показывал действующее
значение). На `<600` у трёх вкладок меньше паддинг и кегль, счётчики спрятаны — иначе
на 360px названия усекались. Правило «две вкладки + воронка» для Уведомлений и
вкладок карточки остаётся.

### 5. Цвета и тексты — токенами, по замерам эталона

- Аватары: пять средних тонов доски (`--pr-avatar-1…5`) с белой буквой
  (`--pr-avatar-text`); бледные тинты читались как пустые кружки.
- `--pr-ls-eyebrow: 0.08em` (было 0.16em): капс-надписи доски разрежены умеренно.
- `--pr-d-fs-title: 15px` — название в строке в одном кегле с body.
- `--pr-info-bg` — голубовато-серая плашка `Callout tone="info"` (настройки).
- `Button`: `ghost` — белая с рамкой; новый `link` — текст без подложки (бирюзовый).
- Нижняя навигация на креме, бейджи янтарные с тёмной цифрой, подпись «Уведомл.»
  (`nav.notificationsShort`); в шапке телефона актёр — один кружок без пилюли.
- Статус словом — строчными (`text-transform: lowercase`), роль — «вы заказчик»
  (`contracts.rowRole*`); слово-действие в строке уведомления и подчёркивание
  контрагента в строках убраны (`CounterpartyLink plain`).
- «Деньги» — кремовая карточка с белыми плитками; мини-профиль рейла — только десктоп.

## Последствия

- Экраны с собственной шапкой на телефоне переводятся на `useShellHeader` +
  `ScreenHeader inShell`; детальные экраны с «‹ назад» — тем же способом (title-слот).
- `Surface bleed` — только для списков; блок с паддингом (`padded`) во всю ширину не
  выходит.
- `text-transform: lowercase` у статуса словом — компромисс для 29 локалей (немецкие
  существительные теряют заглавную); при жалобе носителя — вернуть через отдельные
  ключи строк, не через чип.
- Слово-действие в строке уведомления убрано: тесты кликают по заголовку пункта;
  действие живёт в колонке деталей (десктоп) и по адресу `action.href` (телефон).
- Поиск в «Сделках» на телефоне — первым полем в шите воронки, над списком его нет.
- Новые ключи (16) добавлены во все 29 локалей (паритет ключей — тест `localePacks`).
