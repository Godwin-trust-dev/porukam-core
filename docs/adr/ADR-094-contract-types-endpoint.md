# ADR-094: GET /v1/contract-types — коды типов клиентского дерева для мастера создания

- Статус: принят
- Дата: 2026-08-18
- Связано: ADR-088 (redesign контура сделки, Фаза 2 — создание), ADR-091 (справочники мастера),
  docs/catalog-v2.md §1 (клиентское дерево), docs/tasks/Задача_redesign_contracts-execution-flow-real-api-phase-2-create.md

## Контекст

Мастер создания договора переводится на боевой `POST /v1/contracts` (`ContractCreateSerializer`).
Резолв типа устроен асимметрично (`apps.contracts.services._resolve_contract_type_code`):

- «Услуга»: достаточно `client_option="service"` — код (`services_individual`/`services_business`)
  сервер вычисляет сам по статусу исполнителя (`resolve_service_contract_type_code`);
- «Продажа»/«Аренда»/«Займ»: `client_option` НЕ резолвится — нужен явный `contract_type_code`
  (`sale_personal`/`sale_business`, `rent_items`/`rent_home`, `loan_individuals`), иначе 422.

Фронту эти коды взять неоткуда: списка типов в API нет, а хардкод кодов каталога в SPA нарушает
принцип каталога «данные, не код» (ADR-058 — белый список меняется миграцией, не релизом фронта).

## Решение

Read-only `GET /v1/contract-types[?client_option=]` в `apps.catalog` (рядом с остальными
справочниками ADR-091, тот же слой view → selectors):

- выборка (`selectors.list_client_tree_contract_types`): `is_active=True`, `is_hidden=False`,
  `client_option IS NOT NULL`, `default_segment != excluded` (оборонительно — в сиде excluded и так
  скрыты; создать excluded-тип нельзя, 403, значит и предлагать его нельзя), порядок
  `sort_order, code`;
- `client_option` опционален; невалидное значение → 400 (как обязательные параметры ADR-091);
- ответ `{results: [{code, name, client_option}]}`, `name` локализовано по `Accept-Language`
  через общий `localized_name` (фолбэк ADR-091 §2). Налоговые заметки, сегменты, `available_from`
  фронту на этом шаге не нужны — не отдаём (принцип «не показываем того, чего нет» и минимальный
  контракт);
- права: `AllowAny` — справочник без персональных данных, тот же уровень, что `/spheres`.

## Последствия

- Мастер: плитка «Услуга» шлёт `client_option`, плитки Продажа/Аренда — под-выбор кода из этого
  списка, «Займ» — единственный код оттуда же; фронт не знает кодов заранее.
- Новые типы (Р2: авто/недвижимость и т.д.) появятся в мастере включением в каталоге
  (`is_hidden=False`), без релиза фронта — но только вместе с подключением их форм (ADR-088 Фаза 2:
  превью блокирует отправку типов без подключённой формы).
- Альтернатива «расширить резолв на сервере» отклонена: для продажи/аренды выбор кода —
  пользовательское решение (личное имущество vs бизнес; вещь vs жильё), сервер его вычислить
  не может.
