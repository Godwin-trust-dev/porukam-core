# ADR-147: Якоря доверия для архивных цепочек TSA (SHA-1-корни)

**Статус:** Accepted
**Дата:** 2026-09-02
**Решение принято:** владелец продукта (вариант C из постановки
`docs/tasks/Задача_fix_audit-vault-sha1-root.md`)
**Область:** доказательная архивация, слой меток времени (расширяет ADR-135)

---

## Контекст

ADR-135 закладывал метку времени на суточный чекпойнт от четырёх независимых TSA
с кворумом 2. Архивная цепочка сертификатов каждой метки должна быть
САМОДОСТАТОЧНОЙ: через 10 лет эксперт проверяет метку по файлам экспорт-пакета,
не имея нашего хранилища. Полноту цепочки код определял правилом «последнее
звено самоподписано, и самоподпись проверяется» (`_is_self_signed`).

31.08.2026 обнаружено (разбор с доказательствами — в постановке): метки
`time.certum.pl` выпадают из кворума с ошибкой «цепочка не завершается
самоподписанным корнем», хотя корень `Certum Trusted Network CA` успешно
докачивается по AIA и цепочка фактически полна. Ломается проверка самоподписи:
корень 2008 года подписан `sha1WithRSAEncryption`, и `cryptography`
отказывается проверять SHA-1 **по политике** (`ValueError: Unsupported
signature algorithm`), а наш `except ValueError` не отличает «политика
запрещает» от «подпись не сходится». Подпись при этом криптографически
корректна (проверено низкоуровнево).

Проблема шире Certum: почти все долгоживущие корни до ~2015 года самоподписаны
SHA-1, то есть тот же отказ ждёт любой TSA с таким корнем. Запас отказов
кворума фактически сократился с двух до одного.

**Ключевое наблюдение:** самоподпись корня — не контроль доверия. Любой может
выпустить самоподписанный сертификат с любым именем; доверие к корню возникает
из внешнего якоря (хранилище ОС, CCADB, собственный пин), а не из того, что
корень подписал сам себя. Требование «цепочка кончается самоподписанным
корнем» — контроль ПОЛНОТЫ архива, и его можно обеспечить без проверки
SHA-1-подписи вообще.

---

## Решение

Явный список якорей доверия в репозитории:
`backend/services/audit_vault/trust_anchors/` (DER/PEM-файлы; README каталога
фиксирует происхождение, отпечаток SHA-256 и дату пиновки каждого якоря).
Первый якорь — корень `Certum Trusted Network CA` (подлинность подтверждена
криптографически: `openssl verify -partial_chain` на промежуточном сертификате
живого ответа TSA, постановка §2.6).

Полнота цепочки — по **гибридному правилу** (`tsa._closes_chain`), это
осознанная миграционная форма варианта C:

- **(а) якорь:** последнее звено совпадает с одним из якорей по
  subject + SubjectPublicKeyInfo (побайтно). Проверка самоподписи корня
  НЕ выполняется вовсе — SHA-1 в доказательном контуре не появляется;
- **(б) статус-кво:** последнее звено самоподписано и подпись проверяется
  библиотекой современным алгоритмом — для корней, которые пока не
  запинованы (SwissSign, Sectigo, FreeTSA). Поведение пути (б) не меняется:
  SHA-1 он как не принимал, так и не принимает.

Подписи ПРОМЕЖУТОЧНЫХ звеньев `verify_chain_links` проверяет как раньше,
строгой политикой библиотеки — якорь освобождает только последнее звено от
проверки самоподписи (у Certum промежуточное звено подписано корнем SHA-384,
так что весь проверяемый контур остаётся на современных алгоритмах).

**Намерение на будущее:** по мере пиновки остальных корней путь (б) отмирает,
и список якорей становится ЕДИНСТВЕННЫМ определением полноты. Пиновка нового
якоря — осознанное действие в PR по процедуре из README каталога.

## Рассмотренные варианты

### Вариант A: собственная проверка подписи сертификата, SHA-1 только для самоподписи корня

**За:** минимальная правка; настоящая криптографическая проверка сохраняется
(модуль уже умеет SHA-1 для подписей SignerInfo).
**Против:** SHA-1 появляется в коде доказательного контура; аудитор вправе
поднять флаг на любое упоминание SHA-1 независимо от технических нюансов,
и объяснять «это только целостность файла корня, не доверие» придётся каждый
раз. Оставлен запасным.

### Вариант B: убрать требование полноты, хранить `chain_complete=false`

**За:** ещё меньше кода.
**Против:** ослабляет ровно то свойство (самодостаточность архива), ради
которого правило вводилось. Отклонён.

### Вариант C: явный список якорей доверия ← **выбран**

**За:** SHA-1 не участвует вовсе; появляется явный, проверяемый глазами
перечень якорей — для архивной доказательной системы это самостоятельная
ценность, которой раньше не было (доверие к корню было неявно делегировано
будущей экспертизе).
**Против:** список надо вести; смена корня у TSA — правка в репозитории.
Приемлемо при четырёх TSA и редких ротациях корней.

## Анализ компромиссов

Главный компромисс — **явное управление доверием против «нулевого
обслуживания»**. Правило самоподписи не требовало ведения списка, но и не
давало доверия: оно проверяло только целостность файла корня. Якорь честнее:
полнота цепочки теперь означает «цепочка доведена до корня, который мы
осознанно закрепили», и это прямо то, что предъявляется эксперту.

Второй — **гибрид против чистого списка**. Чистый вариант C сразу потребовал бы
запиновать корни всех четырёх TSA; ошибка в любой пиновке уронила бы работающую
метку. Гибрид ничего не ломает (путь (б) — байт в байт прежнее поведение) и
позволяет пиновать корни по одному, с проверкой на живых ответах.

## Последствия

**Становится проще:**

- Метки Certum возвращаются в кворум: запас отказов снова два из четырёх.
- Спор «SHA-1 в доказательном контуре» снят: подпись корня не проверяется.
- Появился явный перечень якорей доверия с процедурой пиновки.

**Становится сложнее:**

- Каталог якорей — новый артефакт, требующий дисциплины при пиновке
  (криптографическое подтверждение подлинности, фиксация отпечатка на ревью).
- Путь (б) остаётся щелью «любой самоподписанный современный корень закрывает
  цепочку» до тех пор, пока не запинованы все корни.

**Придётся пересмотреть:**

- Запиновать корни SwissSign, Sectigo, FreeTSA и отключить путь (б) —
  список якорей станет единственным определением полноты.
- При ротации корня любым TSA — добавить новый якорь тем же PR-процессом.
