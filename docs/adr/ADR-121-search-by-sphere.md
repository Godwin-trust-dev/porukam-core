# ADR-121: Поиск по сферам — люди по фактам сделок, объединения по сфере и географии (ADR-114 v2)

Дата: 2026-08-24. Статус: принят. Расширение ADR-114; опирается на ADR-117 (сфера и география объединений).

## Контекст

Отсмотр 2026-08-24: «давай в поиск добавим ещё сферы… Я ищу мастера по маникюру в Москве. Я должна
найти мастеров, гильдии, кланы». ADR-114 v1 искал людей только по @хендлу/телефону (ФИО
зашифровано — поиска по имени нет by design), объединения — по имени/хендлу, гео-зоны применялись
к людям, объединения были без локации. ADR-117 дал объединениям обязательную сферу каталога и
географию `world|country|city`.

## Решения

### 1. Сфера резолвится из текста запроса тем же ранжированием, что `GET /spheres?q=`

`apps.dashboards.selectors._match_spheres(query, locale)`: кандидаты — активные сферы каталога с
именами на языке зрителя + ru и именами категорий чек-листов (`catalog.categories.*` из пакетов
— «маникюр» → `beauty` через категорию), ранжирование — `apps.catalog.search.rank_spheres`
(токены, префиксы, опечатки). Берутся первые 3 (`_SPHERE_HITS_LIMIT`) — это каталожная выдача,
а не автодополнение. Ответ несёт `spheres: [{code, name}]`, чтобы фронт показал «по сфере: …».
Запросы-адреса (телефон ≥ 10 цифр) сферу не резолвят; хендл-поиск работает параллельно.

### 2. Люди по сфере — только исполнители с завершёнными сделками в ней

`apps.reputation.selectors.contractor_profile_ids_in_spheres` (read-модель `DealFact`,
`is_completed=True`, пересечение `sphere_codes`) — «репутация на фактах»: единственный сигнал
«человек работает в сфере X», который платформа подтверждает сама. Портфолио (плоский enum
`PortfolioProject.Sphere`, 7 значений, не коды каталога) и «сфера профиля» (поля нет) как источник
ОТКЛОНЕНЫ: самодекларация без фактов, к тому же в другой кодировке. К таким людям применяются
каталожная находимость (`is_visible_in_catalog`, `discoverable_by_handle`) и гео-зона зрителя —
в отличие от точных @хендл/телефон (ADR-114, отсмотр 2026-08-24). В выдаче помечены
`sphere_match: true`.

### 3. Объединения по сфере — с географией объединения

`apps.social.selectors.search_groups_by_sphere(codes, zone, country, city)`: публичные, `sphere_code`
в совпавших; зона `world` не фильтрует; `country` — `world`-объединения + совпадение страны; `city` —
`world` + `country` той же страны + `city` того же города. Результат объединяется с прежним
поиском по имени/хендлу без дублей; в строке — `sphere_code`.

### 4. Что НЕ меняется

Форма ответа расширена совместимо (`spheres`, `sphere_code`, `sphere_match` — необязательные).
`applied_zone` считается как раньше. Поиска по имени людей по-прежнему нет.

## Последствия

- Первые сделки в сфере делают исполнителя находимым по сфере автоматически — без действий с его
  стороны, но только при публичном профиле и `discoverable_by_handle`.
- Запрос вроде «ремонт» может дать до 3 сфер и много объединений — лимиты 20/50 в селекторах
  остаются; пагинация — когда появится нужда.
- Фронт (`feat/web-search-spheres`): чипы найденных сфер, бейдж «по сделкам в сфере» у людей,
  сфера и подсказка в плейсхолдере.
