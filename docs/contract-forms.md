## 0. Что НЕ заполняется руками (автоблоки — из профилей и настроек)

Эти данные попадают в договор без полей формы: **стороны** (ФИО/наименование, статус, реквизиты — из верифицированных профилей, K1; для B2C автоматически полный набор ст. 8–10 ЗоЗПП); **подписант и основание полномочий** (снимок SigningAuthority); **канал коммуникаций** (K6); **ПЭП-условия** (K15); **роль платформы** («оператор инфраструктуры, не сторона»); **налоговые блоки** по статусу исполнителя (V-NPD для СМЗ и т.п.). Правило: всё, что можно взять из верификации и реестров, — не спрашиваем.

## 1. Общие поля любой формы (шапка)

| Поле | Обяз. | Формат / валидация | Примечание |
|---|---|---|---|
| Моя роль | ✅ | выбор: заказчик / исполнитель (продавец / покупатель · арендодатель / арендатор · займодавец / заёмщик) | Определяет, чьи поля предзаполняются |
| Контрагент | ✅ | @handle / прямая ссылка / телефон (если у него вкл. находимость) / «пригласить» (реф-ссылка) | Незарегистрированный → инвайт, договор ждёт его регистрации |
| Способ расчёта | ✅ | из PaymentMethod с честной меткой защиты | Наличные → предупреждение «не попадёт в доказательную базу» (K3) |
| Профиль действия | авто | физлицо / бизнес (X-Acting-Profile) | Влияет на compute_segment |

Валидации шапки: контрагент ≠ сам себе; гейт верификации по уровню операции; `requisites_missing` — если для расчётов сторон нужны реквизиты, а их нет (формулировка без «платного сегмента» — док 28 §2.1).

## 2. 🔧 УСЛУГА (`services_individual` / `services_business` — тип вычисляется)

Самая богатая форма — под ней вся механика этапов. Порядок секций = порядок заполнения.

| # | Секция / поле | Обяз. | Формат / валидация | Куда идёт |
|---|---|---|---|---|
| 1 | Сфера → категория | ✅ | из справочника сфер — **все 17 сфер с полными чек-листами с запуска** (решение 01.08; наполнение — расширенный П-03) | Подбор шаблона (матрица док 18 §5), дефолты категории |
| 2 | Название и описание работ | ✅ | текст; подсказки по категории | K2, заголовок |
| 3 | Место оказания | ✅ | адрес / «удалённо» | K2; V-ACCESS если помещение |
| 4 | Сроки: начало и окончание | ✅ | дата ИЛИ «N дней от гейта этапа» | K4 (ст. 708 — без сроков договор незаключён) |
| 5 | **Дерево этапов** | ✅ ≥1 | конструктор: название, сумма, срок, чек-лист (пункты из шаблонов дока 16 + свои); ветки/листья | Приложение 1 (K2, K7); UX-подсказка дробления (П-13) |
| 6 | Материалы | опц. | позиции: кто поставляет, наименование, кол-во, цена/правило цены, срок «N дней от события» | Приложение 2 (K5) |
| 7 | Цена: тип | ✅ | твёрдая / приблизительная смета (предупреждение п. 5 ст. 709) | K3 |
| 8 | Раскладка оплат | ✅ | по этапам: аванс/постоплата на лист | K3; **валидация: Σ листьев = сумма договора** |
| 9 | Гарантийный срок | дефолт | дефолт категории, редактируемо (B2C — не ниже закона) | K8 |
| 10 | Окно приёмки этапа | дефолт | дефолт категории (П-04), «щедрое» | K7 |
| 11 | Опции модулей | опц. | галочки по сфере: доступ в помещение (V-ACCESS), субподряд (V-SUB: запрещён/разрешён/с согласия), портфолио (V-PORT) и др. по матрице | V-блоки |

**Превью:** полный договор (K1–K15 + включённые V) + Приложение 1 (этапы с чек-листами) + Приложение 2 (материалы). Предупреждения конструктора инлайн («этап без чек-листа — слабая позиция в споре»).

## 3. 📦 ПРОДАЖА (`sale_personal` / `sale_business`)

| # | Поле | Обяз. | Формат / валидация | Куда идёт |
|---|---|---|---|---|
| 1 | Категория товара | ✅ | из категорий sales (док 24 §2.2); **авто/недвижимость → заглушка «скоро»**; продавец-СМЗ → только категории собственного производства | Шаблон, модерация |
| 2 | Наименование и описание | ✅ | текст | V-GOODS |
| 3 | Состояние | ✅ | новый / б-у + описание дефектов | V-GOODS («заявленное состояние» — база C2C-претензий) |
| 4 | Комплектность | опц. | текст/список | V-GOODS |
| 5 | Идентификаторы | опц. (обяз. для электроники) | серийник/IMEI | V-GOODS |
| 6 | Фото товара | опц. | по желанию (решение 01.08); для б/у — рекомендация конструктора «фото фиксирует заявленное состояние — сильнее позиция в споре»; приложенные фото входят в замороженную версию | V-GOODS (если приложены — неотъемлемая часть) |
| 7 | ☑ Продукция своего ЛПХ | опц. (продавец-физлицо) | галочка → налоговая пометка + подсказка условий освобождения (справка, ≤0,5 га) | tax_note |
| 8 | Цена | ✅ | сумма > 0 | K3 |
| 9 | **Тип доставки** | ✅ | выбор: самовывоз / личная передача / доставка до ПВЗ (склада) / курьером до адреса / транспортная компания | V-HANDOVER; определяет состав полей 9а–9в |
| 9а | Адрес | ✅ (кроме «обсудим лично») | адрес передачи / адрес ПВЗ / адрес доставки — по типу из п. 9 | V-HANDOVER |
| 9б | Кто оплачивает доставку | ✅ при доставке | продавец / покупатель / пополам; сумма или «по тарифу перевозчика» | K3/V-HANDOVER |
| 9в | Срок передачи/отправки | ✅ | дата или «N дней от оплаты»; для ТК — трек-номер как подтверждение отправки | V-HANDOVER |
| 10 | Окно осмотра | дефолт **24 ч**, редактируемо | часы: дефолт 24 ч при личной передаче, стороны вписывают своё значение по желанию (решение 01.08); ПВЗ/доставка — отсчёт от получения | V-HANDOVER; приёмка = подтверждение осмотра; риск переходит с подтверждения |

Автоблоки: заверения продавца (собственность, не залог — V-GOODS); B2C — возврат 7 дней + памятка автогенерацией (V-RETURN). **Превью:** ДКП + карточка товара с фото.

| 4 | Срок аренды | ✅ | от–до / посуточно | K4 |

## 5. 🏠 АРЕНДА → Жильё (`rent_home`)

| # | Поле | Обяз. | Формат / валидация | Куда идёт |
|---|---|---|---|---|
| 1 | Объект: адрес, тип (квартира/комната/дом), этаж/площадь | ✅ | адрес обяз.; кадастровый № опц. | V-RENT |
| 1а | **Основание распоряжения объектом** | ✅ | выбор: собственник (реквизиты записи о праве / выписка ЕГРН — фото/скан) · представитель по нотариальной доверенности (реквизиты + документ; проверка по reestr-dover.ru — подсказка нанимателю) · наниматель с правом сдачи в поднаём (письменное согласие наймодателя — документ) | K1 (преамбула: «действующий на основании…»); документ — в доказательную базу сделки |
| 1б | Чек-лист нанимателя | авто | подсказка: сверить адрес/кадастровый № с документом-основанием; помнить, что заказать свежую выписку ЕГРН может сам собственник (ФИО в открытых данных скрыты с 2023) — попросить её при осмотре | предупреждение конструктора |
| 2 | Срок найма: **краткосрочная** (`term_kind=short_term` → кол-во дней, обяз., ≥ 1) или **долгосрочная** (`term_kind=long_term`, дефолт → месяцы, опц., дефолт **11 мес**) | ✅ выбор ветки (дефолт long_term — совместимость с сохранёнными form_data) | долгосрочная ≥ 1 года → предупреждение о регистрации обременения (ст. 674); отсмотр 2026-08-24 | K4 |
| 3 | Плата: сумма/мес + день оплаты | ✅ | периоды = этапы; календарь платежей | K3 |
| 4 | Коммунальные платежи | ✅ | включены / по счётчикам / фикс (подсказка о налоговой разнице для наймодателя) | V-RENT |
| 5 | Депозит | опц. | сумма, условия возврата (ст. 381.1) | V-RENT |
| 6 | Проживающие | ✅ | список (ФИО), животные ☑ / курение ☑ | V-RENT |
| 7 | Опись имущества | рекомендовано | позиции + состояние + фото | акт заселения (наша сильнейшая механика) |
| 8 | Показания счётчиков | рекомендовано | числа + фото | акт заселения |
| 9 | Порядок расторжения | автоблок | ст. 687 — честно показываем асимметрию (наниматель — уведомление 3 мес; наймодатель — через суд) | K10 |

Наймодателю — подсказка НПД для жилья / НДФЛ (флаг ФНС-03). **Превью:** договор + акт заселения с описью и счётчиками (подписывается при заселении).

## 6. 💰 ЗАЙМ (`loan_individuals`)

| # | Поле | Обяз. | Формат / валидация | Куда идёт |
|---|---|---|---|---|
| 1 | Сумма займа | ✅ | > 0; при ≥ 10 тыс — пометка «письменная форма обязательна — закрыта этим договором» (ст. 808) | V-LOAN |
| 2 | Проценты | ✅ **явный выбор** | «беспроцентный» / ставка % годовых; ≤ 100 тыс дефолт — беспроцентный (п. 4 ст. 809); ставка > 2× ключевой → предупреждение о ростовщических (п. 5 ст. 809) | V-LOAN |
| 3 | Срок и график возврата | ✅ | единовременно (дата) / график платежей (конструктор: равные / произвольные, **≤ 60 платежей** — решение 01.08) — **график = этапы**; валидация: Σ графика = сумма + проценты | K4, этапы |
| 4 | Способ передачи денег | ✅ | через платформу (рекомендуется: платёж = доказательство передачи — займ реальный, ст. 807) / вне платформы → предупреждение + поле «подтверждение передачи» | K3 |
| 5 | Досрочное погашение | дефолт: разрешено | ☑ | V-LOAN |
| 6 | Цель займа | опц. | текст (целевой займ — ст. 814) | V-LOAN |

Автоблоки: расписка-сателлит (генерируется при подтверждении передачи денег); займодавцу — уведомление про НДФЛ с процентов; счётчик систематичности (предупреждение при N займов). **Превью:** договор + образец расписки + график платежей.

## 7. Кросс-типовые предупреждения (генерируются, не заполняются)

Наличные/вне платформы → «без защиты и доказательной базы» · заказчик-организация + исполнитель-физлицо → уведомление о налоговом агентстве (док 27 §5) · систематичность (услуги/продажи/займы) → подсказка НПД / предупреждение · B2C-режим → законные права потребителя не урезаются (блокировка «невозвратных депозитов» и т.п. на уровне конструктора) · этап без чек-листа → «слабая позиция в споре».
