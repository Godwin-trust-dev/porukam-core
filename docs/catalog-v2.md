## 0. Утверждённые решения (сессия 01.08)

1. **Клиентское дерево ≠ юридическая типология.** Клиент выбирает из **четырёх жизненных сценариев**: **Услуга · Продажа · Аренда · Займ**. Сегменты ADR-058 (`free_c2c` / `paid_business` / `special` / `excluded`) остаются под капотом — `compute_segment` вычисляет их по типу и статусу сторон; в UI сегмент не виден и не подаётся как «платный/бесплатный» (док 29 §3).
2. **Каталог Р1 сокращён до четырёх живых сценариев.** Дарение, мена, безвозмездная помощь — **в Р1 отсутствуют** (вариант «а»; типы остаются в справочнике скрытыми с `available_from = Р2` — коды не теряем).
3. **Аренда — из special в стандартные договоры**, две ветки внутри опции: **вещи** и **жильё**. «Стандартный» = умный шаблон с зашитыми правильными дефолтами (см. §2).
4. **Займ — стандартный договор** (шаблон V-LOAN, док 24 §3.1).
5. **Special в Р1 не трогаем и не показываем**: продажа/дарение недвижимости и транспорта — честная заглушка «этот тип сделки скоро» при попытке (не молчаливое оформление обычным ДКП — не создаём иллюзию, что закрыли перерегистрацию).
6. **ЛПХ — не отдельный тип, а галочка** внутри «Продажи» («продукция своего личного хозяйства») — меняет налоговую пометку.
7. **Флоу для всех сценариев един:** выбор опции → ветка/сфера → **форма полей** → превью документа → отправка на согласование (дальше — существующий контур Ф2: разногласия → заморозка → подписание).
8. **Платформа — не налоговый агент.** Мы не касаемся денежного потока (ADR-055/060) и не исчисляем налоги сторон. Наша роль — **уведомления и рекомендации** (§5). Единственный случай агентства создаёт сам закон — у заказчика-организации при исполнителе-физлице; наше уведомление ему об этом — часть защиты платформы.

## 1. Клиентское дерево выбора

```
Новый договор
├─ 🔧 УСЛУГА ──► каталог сфер (ремонт — стартовая вертикаль; несколько сфер)
│      └─ тип вычисляется автоматически:
│         исполнитель без бизнес-статуса → services_individual (free_c2c)
│         исполнитель СМЗ/ИП/юрлицо   → services_business (paid_business*)
│         * сегмент — каталожно-налоговая роль; всё бесплатно (v2)
│         Полная механика: этапы, чек-листы, приёмка, доказательства
├─ 📦 ПРОДАЖА ──► стандартный ДКП (sale_personal / sale_business — по статусу продавца)
│      ├─ ☑ «продукция своего личного хозяйства» → налоговая пометка ЛПХ
│      └─ предмет = авто/недвижимость → заглушка «скоро» (special, Р2)
├─ 🏠 АРЕНДА
│      ├─ Вещи  ──► стандартный договор (rent_items): опись с фото,
│      │            депозит 381.1, перенос риска с акта передачи
│      └─ Жильё ──► стандартный договор (rent_home): дефолт 11 мес
│                   (≥ 1 года — предупреждение о регистрации, ст. 674),
│                   депозит 381.1, опись + счётчики, периоды = этапы
└─ 💰 ЗАЙМ ──► стандартный договор (loan_individuals): сумма, проценты
               (всегда явное поле; ≤100 тыс — беспроцентный по умолчанию),
               график возврата = этапы, расписка-сателлит автогенерацией

Каждая ветка: форма полей → превью документа → на согласование (контур Ф2)
```

## 2. Каталог Р1 (сид, `available_from = Р1`)

| Код | Опция UI | Сегмент (под капотом) | Налоговая пометка (суть) | Основание | Умные дефолты шаблона |
|---|---|---|---|---|---|
| `services_individual` | Услуга | free_c2c (вычисляется: исполнитель — физлицо без статуса) | НДФЛ у исполнителя; заказчик-организация — налоговый агент по закону (уведомляем его); счётчик систематичности + подсказка НПД | ГК гл. 37/39; ФНС-06 🟩; тест Р-1 | Этапы/чек-листы из справочника сфер (П-03) |
| `services_business` | Услуга | paid_business (вычисляется: исполнитель — СМЗ/ИП/юрлицо) | СМЗ: чек НПД, лимит 2,4 млн, проверка статуса; ИП/ООО: акт | ГК гл. 37/39; ФЗ-422 | То же + закрывающие документы; ADR-049 (подмена трудовых) |
| `sale_personal` | Продажа | free_c2c (продавец — физлицо, личное имущество) | Движимое ≥ 3 лет — освобождение; иначе вычет 250 тыс/расходы; ☑ ЛПХ → п. 13 ст. 217 НК (условия: ≤ 0,5 га, без наёмных, справка — ФНС-08 🟩) | П. 5 ч. 2 ст. 6 ФЗ-422 (ФНС-07 🟩); ЗоЗПП к C2C не применяется (Пленум ВС № 17) | V-GOODS + V-HANDOVER: описание/состояние/фото, окно осмотра, фиксация передачи |
| `sale_business` | Продажа | paid_business (продавец — бизнес) | ИП/ООО — по режиму; СМЗ — только собственное производство (ст. 4 ФЗ-422, фильтр категорий) | ГК гл. 30; ЗоЗПП ст. 26.1 (B2C: возврат 7 дней, памятка автогенерацией) | + V-RETURN (B2C); модерация по блок-листу (док 24 §2.3) |
| `rent_items` | Аренда → Вещи | free_c2c / paid_business по статусу арендодателя | Систематическая сдача движимого — НПД разрешён; разовая — НДФЛ | ГК гл. 34; ст. 607 | V-RENT: идентификация вещи, фото при передаче/возврате, депозит 381.1, V-RISK-TRANSFER |
| `rent_home` | Аренда → Жильё | free_c2c / paid_business по статусу наймодателя | НПД 4/6% для жилья разрешён (апартаменты — нет) или НДФЛ; флаг ФНС-03 🟥 | ГК гл. 35; ст. 674 (регистрация при ≥ 1 года) | Дефолт срока 11 мес + предупреждение; депозит 381.1; опись с фото + счётчики; периоды = этапы; асимметрия расторжения ст. 687 — показываем честно |
| `loan_individuals` | Займ | free_c2c | Тело — не доход; проценты — НДФЛ займодавца (самодекларирование); матвыгоды у заёмщика нет (ст. 212 НК) | ГК гл. 42; ст. 808 (письменная форма от 10 тыс — закрывает наш ПЭП) | Проценты — всегда явное поле (п. 4 ст. 809); предупреждение о ростовщических (п. 5); график = этапы; расписка-сателлит; платёж через платформу = доказательство передачи. Красные линии: без матчинга (259-ФЗ), без рекламы займов; счётчик систематичности (ст. 14.56 КоАП) |

## 3. Отложено из Р1 (`available_from = Р2`, в UI скрыты)

| Код | Что | Почему отложено / что при попытке |
|---|---|---|
| `gift_movable`, `barter_personal`, `gratuitous_help` | Дарение, мена, безвозмездная помощь | Решение §0 п. 2: редкие сценарии, не раздуваем первый экран. Кодов в UI нет |
| `sale_vehicle`, `sale_real_estate`, `gift_registered` | Продажа/дарение транспорта и недвижимости | Special: переход права, реестры (V-TITLE, Росреестр). Клиент указал авто/недвижимость в «Продаже» → заглушка «этот тип сделки скоро» |
| Портфель регулярных договоров | Панель арендодателя | Волна подписки (финмодель v2 §8.1 п. 3; П-14). Одиночный договор найма — уже в Р1 (`rent_home`) |

## 4. Excluded — не поддерживается, скрыт (без изменений)

`shares_securities` (доли/паи/ЦБ) · `crypto_dfa` (цифровая валюта/ЦФА) · `employment` (трудовые — красная линия М-07) · `loan_matching` (матчинг займов — 259-ФЗ). Не видны нигде; попытка — запрет `compute_segment`.

## 5. Налоговая позиция платформы (в оферту и тексты уведомлений)

**Мы не налоговый агент и не налоговый консультант.** Платформа не касается денежного потока сторон, не исчисляет и не удерживает налоги. Все налоговые пометки — информация с дисклеймером, решение и обязанность — у сторон. Ключевые уведомления (автоматические, по типу договора и статусам сторон):

1. Заказчику-организации при исполнителе-физлице: «закон делает вас налоговым агентом — НДФЛ + взносы» (это его обязанность по НК, не наша).
2. Исполнителю-физлицу при росте систематичности: подсказка оформить НПД (счётчик, ADR-034).
3. Продавцу-физлицу: правила «3 года / вычет 250 тыс»; при ☑ ЛПХ — условия освобождения.
4. Наймодателю: НПД для жилья / НДФЛ; при сроке ≥ 1 года — регистрация обременения.
5. Займодавцу: НДФЛ с процентов, самодекларирование.

## 6. Пограничные позиции (флаг `needs_official_clarification`)

| Позиция | Консервативная политика Р1 | Снимается |
|---|---|---|
| Систематичность продаж/займов физлица | Счётчик + предупреждение (пороги — конфиг) | Письмо №1 ФНС (ФНС-01/02) / акты ФЗ-289 |
| Аренда жилья: НПД vs НДФЛ vs C2C | Пометка обоих режимов + «проверьте свой случай» | ФНС-03 |
| «Дистанционная продажа» при личной передаче | Памятку о возврате генерируем всегда | Б4-волна 2 (оферта) |

Письмо №1 в ФНС — от ООО в сентябре; пересегментация по ответам — данные, без релиза.

## 7. Дельта к сиду этапа 2

1. Поля `available_from` (Р1/Р2) и `needs_official_clarification` — миграция.
2. Состав Р1 — семь кодов §2; `gift_movable`/`barter_personal`/`gratuitous_help` → Р2 hidden; special — Р2 hidden + заглушка; excluded — как было.
3. Атрибут «ЛПХ» — булево поле договора типа `sale_personal` (меняет tax_note), не отдельный тип.
4. UI-группировка: поле `client_option` (`service`/`sale`/`rent`/`loan`) для четырёх опций первого экрана.
5. `tax_note_i18n` — тексты §2 + единый дисклеймер-суффикс; `legal_basis` — коды дока 23 (добавить недостающие: п. 18.1 ст. 217, ст. 381.1, 259-ФЗ ×2).
6. Тесты `compute_segment`: Р-1; excluded → запрет; СМЗ-продавец → фильтр собственного производства; авто/недвижимость → 409 «not_yet_supported».

## 8. Следующий шаг: поля форм (реестр П-16)

Для каждого из семи типов Р1 — утвердить состав полей формы (обязательные/опциональные, валидации, что попадает в превью документа). Черновик соберёт Claude на основе шаблонов конструктора (док 18, модули V-*) и дока 24 — отдельным документом к сессии с владельцем. Это вход для постановки Э4 (contracts) и фронтенд-среза.
