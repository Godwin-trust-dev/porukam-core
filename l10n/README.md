# Языковые пакеты (l10n)

Инфраструктура — Л.2 (ADR-077), поверх фолбэк-
механизма ГВ.5 (`backend/common/i18n.py`, ADR-075). Контент — внешний
конвейер переводов: пакеты генерируются партиями по волнам (все стартуют как
`machine`), затем импортируются командой и спот-проверяются владельцем.

**Никаких runtime-переводов и внешних API.** Все тексты — статические
JSON-файлы в этой директории, загружаемые в БД командой `import_l10n_pack`
(`backend/apps/l10n`). RU-интерфейс и RU-тексты не участвуют в этом
механизме (свой контур, не тронут).

## Формат: `l10n/packs/<code>.json`

Один файл на язык. `<code>` — BCP-47 (`es`, `pt-BR`, `zh-Hans`, …), должен
совпадать со значением поля `locale` внутри файла.

```json
{
  "locale": "es",
  "name": "Español",
  "rtl": false,
  "quality": "machine",
  "pack_version": 1,

  "errors": {
    "otp_invalid_code": "El código es incorrecto. Verifíquelo e inténtelo de nuevo."
  },

  "notifications": {
    "contract.signed": {
      "subject": "Contrato firmado",
      "body": "\"{contract_title}\" ha sido firmado por ambas partes."
    }
  },

  "catalog": {
    "spheres": {"design": "Diseño"},
    "contract_types": {"services_individual": "Servicios (particular)"},
    "client_tree": {"service": "Un servicio o trabajo"},
    "categories": {"renovation.turnkey": "Reforma integral llave en mano"}
  },

  "clauses": {
    "K2@1": "Texto del bloque K2, versión 1"
  },

  "ui": {
    "common.sign": "Firmar"
  },

  "legal": {
    "translation_disclaimer": "Está viendo una traducción por conveniencia…",
    "custom_terms_notice": "Texto redactado por una de las partes. No traducido por la plataforma.",
    "no_legal_force_disclaimer": "Registramos hechos…",
    "tos": null,
    "privacy": null,
    "consents": {"pd_processing": null, "profile_public": null}
  }
}
```

### Поля шапки (обязательные)

| Поле | Тип | Значение |
|---|---|---|
| `locale` | строка | BCP-47, совпадает с именем файла |
| `name` | строка | само-название языка (то, что видит носитель в переключателе) |
| `rtl` | bool | `true` для языков с письмом справа налево (`ar`/`fa`/`he`/`ur`, …) |
| `quality` | `canonical` \| `reviewed` \| `machine` | честный флаг качества — `machine` показывается на фронте с пометкой «beta» |
| `pack_version` | целое ≥ 1 | версия ЭТОГО файла целиком (шапка + все namespaces) — растёт при любой правке содержимого |

Ключи, начинающиеся с `_` (например `_note`), — комментарий составителя
пакета, игнорируются импортом.

### Namespaces (все необязательны — частичный пакет валиден)

- **`errors`** — `{code: текст}`, тексты `title` application/problem+json
  (`code` — из открытого множества кодов, используемых
  `DomainAPIError(code=…)` по всему бэкенду; отсутствие ключа для реального
  кода — не ошибка, просто пакет ещё не покрывает этот код).
- **`notifications`** — `{topic: {"subject": …, "body": …}}`. `topic` —
  код шаблона (`apps.notifications.NotificationTemplate.code`). `subject`/
  `body` можно задавать по отдельности — отсутствующее поле остаётся
  незаполненным (фолбэк — на стороне потребителя).
- **`catalog`** — вложенный на один уровень: `{sub_namespace: {code:
  текст}}`. Состав `sub_namespace` — по факту сгенерированных пакетов, не
  жёсткий список (сейчас: `spheres`, `contract_types`, `client_tree`,
  `checklists` — влиты `merge_checklists.py`, П-03, и `categories` —
  имена видов работ `{"<сфера>.<код>": текст}` для `GET /work-types` и
  кандидатов поиска сфер, ADR-097; `materials` из первоначальной
  постановки Л.2 добавится тем же способом позже).
- **`clauses`** — `{"<block_id>@<template_version>": текст}` — переводы
  `ClauseTemplate` (Л.1, `feat/contracts-l10n`, отдельная ветка); ключ —
  строка, без ссылочной целостности на модель на уровне импорта (нижний
  слой `apps.l10n` ни от кого не зависит) — до того, как Л.1 начнёт
  писать `block_id@version`, namespace может отсутствовать целиком.
- **`ui`** — строки интерфейса фронта (заметка «Фронтенд» во
  внутренней постановке — тот же внешний конвейер, тот же файл; бэкенд
  эту секцию не обрабатывает, только хранит и отдаёт как часть пакета).
- **`legal`** — юртексты «for convenience only» (доку 32). `null` —
  валидное значение («ещё не заполнено», это НЕ ошибка формата); `consents` —
  вложенный объект `{consent_type: текст|null}`, пустой до Ю-23.
  Ключи документов платформы — `privacy`, `tos`, `document_notice` — руками в
  этом файле НЕ правятся: они вливаются из `docs/legal/<code>/` скриптом
  `merge_legal.py` (см. «Юр-документы платформы» ниже).

Неизвестный top-level ключ (не namespace из списка выше и не `_`-комментарий)
— пакет отклоняется целиком, импорт не начинается (валидация — до записи в БД).

## Импорт

```
python manage.py import_l10n_pack l10n/packs/es.json
```

Идемпотентно (тот же `pack_version` + то же содержимое — no-op),
версионировано (`pack_version` меньше уже импортированного —
отказ; тот же `pack_version`, но другое содержимое — отказ, конфликт
версии, увеличьте `pack_version` в файле и повторите). Автосоздаёт/
обновляет `Locale` из шапки файла — `enabled` при этом не трогается
(`True` только при первом создании; включение/выключение языка на фронте —
отдельное ручное действие, например задержка волны B3 до готовности
RTL-вёрстки — см. ниже).

### Изменили пакет — поднимите `pack_version` и обновите lock

Импортёр отказывает пакету с тем же `pack_version` и другим содержимым
(`PackVersionConflictError`) — так 2026-08-20 упал деплой: ключ добавили во
все 29 пакетов, версию не подняли. Стражник без БД — `l10n/packs.lock.json`
(слепок `pack_version` + checksum) и тест `apps/l10n/tests/test_packs_lock.py`:

```bash
# после любой правки l10n/packs/<code>.json:
#   1) pack_version += 1 в каждом изменённом пакете
#   2) перезаписать lock
python l10n/lock_packs.py
# проверить без записи (то же, что делает тест):
python l10n/lock_packs.py --check
```

### Реимпорт `ru`

`ru` — единственная locale с уже ревьюленным вручную контентом (RU-контур,
`quality=reviewed`). Если пакет `l10n/packs/ru.json` когда-нибудь появится
и для `ru` уже есть импортированный пакет, команда перед записью печатает
diff по текстам с текущим пакетом и для каждого РЕАЛЬНОГО конфликта (текст
был и там, и там, и отличается — не для добавленных/снятых ключей, там
оставить нечего) спрашивает `[o]старое / [n]новое`:

```
$ python manage.py import_l10n_pack l10n/packs/ru.json
ru: 1 отличий от текущего пакета
  errors.otp_invalid_code:
    - 'Неверный код'
    + 'Код неверен'
    оставить [o]старое / [n]новое? [n]
```

`--yes`/`-y` — не спрашивать, оставить текст из нового пакета
(неинтерактивные прогоны/CI). Для остальных языков (нет ревью вручную,
пакет — единственный источник) diff/вопрос не показываются никогда.

## Фолбэк-цепочка

`запрошенный язык → en` (не до `ru` — RU-контур остаётся на своём
отдельном механизме, ГВ.5). Каждая точка выдачи текста читает через
`apps.l10n.selectors` (`get_error_title`, `get_notification_text`,
`get_catalog_text`, `get_clause_text`, `get_legal_text`) — расширение
существующего механизма ГВ.5, не дубликат: `common/i18n.py`/
`common/api/exceptions.py` уже подключены (заголовки ошибок на языке
запроса), остальные точки подключаются по мере контент-волн.

## RTL

`rtl: true` в пакете — честный факт о письменности языка, импорт его не
блокирует. Условие включения RTL-языков (`ar`/`fa`/`he`/`ur`) — готовность
вёрстки (`dir="rtl"`, зеркалирование лэйаута) — **выполнено**: фундамент
ADR-079 §2 (логические CSS-свойства + `useHtmlLangDir`) проверен на `ar` на
стартовых поверхностях, и языки включены (ADR-089). Проверка зафиксирована
тестом `web/tests/rtlLaunchSurfaces.test.tsx` — он же сканирует CSS стартовых
экранов на физические `left/right`, которые не зеркалятся.

Фронт по-прежнему обязан проверять поле `rtl`/`dir` ответа `/v1/locales`, а не
полагаться на список языков волны B3: `ur` пришёл волной B2, а `dv` и другие
RTL-письменности могут прийти позже.

## Волны контент-пакетов

Состав волн — A/B1/B2/B3/C (внутренняя постановка, не публикуется). На момент написания этого README волны A/B1/B2 уже
сгенерированы (`l10n/packs/*.json`, кроме `en`/`ru` — те заводятся сидом
`apps.l10n` миграции 0002, не пакетом) и ждут импорта командой. Волна B3
(`ar`/`fa`/`he`) сгенерирована и ВКЛЮЧЕНА в feat/l10n-launch-surfaces: RTL-фундамент
ADR-079 §2 проверен на `ar` (зеркальная раскладка стартовых экранов), см. ADR-089.

## Долив недостающих ключей: `l10n/patches/` + `apply_pack_patch.py` (ADR-095)

Волна привозит пакет целиком, но НЕ гарантирует полноты: ключ, который волна
не завела, просто отсутствует, и фолбэк-цепочка ниже отдаёт EN-текст без
всякой ошибки. Так 27 из 29 языков жили без половины `notifications`/`errors`
— заметить это можно было только глазами. Точечная досыпка идёт патчем:

```
python3 l10n/apply_pack_patch.py l10n/patches/<файл>.json [...]
```

Формат патча — те же неймспейсы, что у пакета, но сгруппированные по языку:
`{"de": {"errors": {...}, "notifications": {"<топик>": {"subject": ..., "body": ...}}}}`.

Скрипт **никогда не перезаписывает существующее значение** (пустая строка
считается дыркой, не переводом): существующий текст всегда старше и ближе к
ревью носителем, чем машинный долив. `pack_version` бампается на +1 у тех
языков, куда что-то реально добавилось, — как в `merge_checklists.py`/
`merge_legal.py` и по той же причине (см. «Импорт» выше: та же версия с
другим содержимым — `PackVersionConflictError`, а в деплое это красный джоб,
а не «пакет не обновился»). Повторный прогон того же патча — no-op, версия
не растёт.

Полноту стережёт тест `backend/apps/l10n/tests/test_packs_coverage.py`:
ключ каждого топика из `settings.NOTIFICATION_TOPIC_TEMPLATES` есть во ВСЕХ
пакетах, набор `{placeholder}` совпадает с EN-каноном, `errors` без дырок
относительно EN. Он проверяет наличие и форму, не качество перевода — качество
по-прежнему спот-проверяет человек.

## Чек-листы (П-03): `l10n/checklists/` — staging переводчиков, не деплой-путь

`_source.ru.json` — не языковой пакет (`_`-префикс — маркер, ничто из
описанного ниже его не трогает), а исходник для конвейера: плоский
`catalog.checklists.<slug>` → RU-текст, регенерируется командой
`python manage.py export_checklists_i18n --output l10n/checklists/_source.ru.json`
(ADR-081) после каждого ревью `docs/content/checklists/CL-*_GLOBAL.md`.
Переводы приходят в эту же папку как `<code>.checklists.json` — частичный
языковой пакет (шапка `locale`/`quality`/`pack_version` + секция
`catalog.checklists` с теми же слагами).

**`<code>.checklists.json` НЕ подхватывается `import_l10n_pack` напрямую**
(так задумывалось изначально — не сработало на практике, ADR-083). `LocalePack`
— одна строка на locale с одним `pack_version`/`checksum` на пакет целиком
(ADR-077); второй независимый `import_l10n_pack` на ту же locale либо падает
по версии, либо молча стирает `errors`/`notifications`/`ui`/`legal` предыдущим
импортом. Путь в прод — на уровне ФАЙЛОВ, до деплоя:

```
python3 l10n/merge_checklists.py   # валидирует и вливает catalog.checklists
                                    # из l10n/checklists/*.checklists.json
                                    # в l10n/packs/<code>.json, бампает
                                    # pack_version; l10n/checklists/_source.ru.json
                                    # под маску не попадает и не трогается
```

После слияния `l10n/packs/<code>.json` едет обычным деплой-циклом
(`import_l10n_pack` из `.github/workflows/deploy-staging.yml`, без изменений
в нём) — деплой ничего не знает про `l10n/checklists/`, эта папка не COPY'ится
ни в один образ. Подробности решения и почему не второй деплой-цикл —
ADR-083.

## Юр-документы платформы: `docs/legal/<code>/` — источник истины, пакет — транспорт

Исходники `docs/legal/` в публичный репозиторий не входят: здесь доступен только собранный блок `legal` в `packs/*.json`.

Privacy Policy и Terms of Service (плюс оговорка об основной версии) живут
markdown-файлами по языкам, ТЕМ ЖЕ приёмом, что чек-листы выше (ADR-083):

```
docs/legal/en/privacy.md      ← эталон структуры (authoritative, решение 17.08.2026)
docs/legal/en/terms.md
docs/legal/en/notice.md        ← оговорка «основная версия — английская», один абзац
docs/legal/<code>/…            ← то же на 28 остальных языках
```

Почему markdown, а не сразу строки в пакете: юр-текст ревьюится и правится как
ТЕКСТ (владелец, юр-трек Ю-23), а не как JSON-значение с экранированными
переводами строк; файл даёт осмысленный `git diff` по абзацам.

```
python3 l10n/merge_legal.py            # вливает в legal.privacy / legal.tos /
                                       # legal.document_notice пакетов, бампает
                                       # pack_version; идемпотентно
python3 l10n/merge_legal.py --check    # только валидация, без записи
python3 l10n/merge_legal.py es de      # конкретные языки (смоук)
```

Валидация перевода — против эталона `en`, до любой записи: число разделов
`## `, число строк markdown-таблиц, номер версии в шапке, набор адресов ссылок
и e-mail. Это ловит обрезанный машинный перевод, потерянную таблицу и
подменённую ссылку — три самые частые поломки контентной волны. Тесты
скрипта — `l10n/test_merge_legal.py` (`uv run pytest ../l10n` из `backend/`
или `python -m pytest l10n/`).

Отдаёт документы `GET /v1/legal/<doc>` (`privacy` | `terms`) — публичный, с
языком в `?locale=`; ответ несёт и фактический язык (честный признак
EN-фолбэка), и `quality` для тихой пометки «машинный перевод». Фронт рисует
его `LegalDocumentSheet` (`@porukam/ui`).

**Формулировка оговорки (`notice.md`) — ЧЕРНОВИК до финального текста от
владельца.** Смысл зафиксирован (основная версия — английская, при
расхождении преимущественную силу имеет английский текст), точные слова
могут измениться; менять их нужно в `docs/legal/<code>/notice.md` и заново
прогнать `merge_legal.py`.
